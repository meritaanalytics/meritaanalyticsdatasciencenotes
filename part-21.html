Interview Preparation

The questions data and credit-risk analyst interviews really ask, with short model answers and tiny code you can run.

In this part
  • Answer core Python, pandas and SQL questions in two or three clear sentences.
  • Explain p-values, confidence intervals, overfitting, leakage and metrics in plain words.
  • Handle machine learning, deep learning and LLM basics questions without jargon.

  • Tell a behavioural story with the STAR method.

#21.1 How to use this question bank

An interviewer wants to see three things: that you know the idea, that you can say it simply, and that you can show it in code or with a number. Practise out loud. A good answer is definition, example, caution in about thirty seconds.

  • Cover the model answer, answer aloud, then compare.
  • Where a question has a code cell, run it and change one thing to see what happens.
  • If you cannot answer, the Part number in brackets tells you where to reread.

Style. Say 'I would check' and 'it depends on' with a reason. Honest uncertainty with a method beats a confident wrong answer. Thresholds quoted below are illustrative; always use your employer's policy.

import numpy as np
import pandas as pd
print("ready")

#21.2 Python questions (Part 2)

Question Model answer
List versus tuple versus set versus dict? List: ordered, changeable. Tuple: ordered, fixed. Set: unique items, fast membership test. Dict: key to value lookup.
What is a mutable object? One that can change in place (list, dict, set). Strings, tuples and numbers cannot, so s.upper() returns a new string.
is versus ==? == compares values; is asks if two names point to the same object.
What is a list comprehension and when not to use one? A compact loop that builds a list. Avoid it when the logic needs several lines; a normal loop reads better.
*args and **kwargs? A function takes any number of positional (tuple) or keyword (dict) arguments.
What does a generator do? Yields one item at a time using yield, so a huge file or range does not sit in memory.
How do you handle errors? try / except for the specific error you expect, finally for cleanup, and raise clear messages.

Two questions that nearly always appear as code: the mutable default argument trap and a quick frequency count.

def add_bad(x, bucket=[]):          # the list is created ONCE, then shared
    bucket.append(x)
    return bucket

def add_good(x, bucket=None):
    bucket = [] if bucket is None else bucket
    bucket.append(x)
    return bucket

print(add_bad(1), add_bad(2))       # surprise: the second call remembers the first
print(add_good(1), add_good(2))

[1, 2] [1, 2]
[1] [2]
from collections import Counter
sms = "pay bill send money send airtime pay bill send".split()
print(Counter(sms).most_common(2))
print({w: sms.count(w) for w in set(sms)} == dict(Counter(sms)))

#21.3 NumPy and pandas questions (Parts 3, 4)

Question Model answer
Why is NumPy faster than a list loop? Arrays hold one data type in one block of memory and loops run in compiled code (vectorisation).
What is broadcasting? NumPy stretches a smaller array to match a larger one when the shapes are compatible.
Series versus DataFrame? A Series is one labelled column; a DataFrame is a table of Series sharing an index.
loc versus iloc? loc selects by label; iloc by integer position.
merge versus concat? merge joins on keys like SQL; concat stacks frames along rows or columns.
How do you find and treat missing data? isna().sum(), ask why it is missing, then drop, fill (median, group median) or flag. Never fill blindly.
What is the SettingWithCopy problem? Changing a slice may not change the original. In pandas 3 copy-on-write makes this safe: assign with loc.

A classic live task: clean a column, then answer a business question in one chain.

orders = pd.DataFrame({
    "county": [" nairobi", "Kisumu ", "NAIROBI", "kisumu", "Nakuru", "nairobi"],
    "amount": [1200, 800, np.nan, 950, 400, 1500],
})
orders["county"] = orders["county"].str.strip().str.title()
orders["amount"] = orders["amount"].fillna(orders.groupby("county")["amount"].transform("median"))
orders.groupby("county")["amount"].agg(["count", "sum"]).sort_values("sum", ascending=False)

Another favourite: a join that multiplies rows. Always check the row count after a merge.

left = pd.DataFrame({"cust": [1, 2], "limit": [10000, 5000]})
dup = pd.DataFrame({"cust": [1, 1, 2], "txn": [300, 200, 50]})
merged = left.merge(dup, on="cust")

#21.4 SQL questions (Part 6)

Question Model answer
WHERE versus HAVING? WHERE filters rows before grouping; HAVING filters groups after aggregation.
INNER versus LEFT JOIN? INNER keeps matches only. LEFT keeps every left row and fills NULL where nothing matches.
COUNT(*) versus COUNT(col)? COUNT(*) counts rows; COUNT(col) skips NULLs.
What is a window function? A calculation across related rows (rank, running total, previous value) that keeps every row.
How do you remove duplicates? SELECT DISTINCT, or ROW_NUMBER() per key and keep number 1.
What is a CTE? A named temporary result set from WITH, which makes long queries readable.

Run the three patterns that decide most SQL screens: top-N per group, an anti-join and a running total.

import sqlite3
con = sqlite3.connect(":memory:")
pd.DataFrame({"loan_id": range(1, 8), "county": list("AABBBCC"),
              "principal": [10, 30, 20, 50, 40, 15, 25],
              "paid": [1, 0, 1, 1, 0, 1, 0]}).to_sql("loans", con, index=False)

top = pd.read_sql("""SELECT * FROM (SELECT loan_id, county, principal,
         ROW_NUMBER() OVER (PARTITION BY county ORDER BY principal DESC) AS n FROM loans) WHERE n = 1""", con)
print(top[["county", "loan_id"]].to_string(index=False))
run = pd.read_sql("""SELECT loan_id, SUM(principal) OVER (ORDER BY loan_id) AS running FROM loans""", con)
print(run["running"].tolist())

SQL or pandas? Say which tool fits: SQL to filter and aggregate large tables close to the data, pandas for cleaning and modelling, Power BI for sharing results. A strong answer names one query and one pandas line that give the same number, and says you would reconcile the two.

#21.5 Statistics questions (Part 8)

Question Model answer
Mean, median or mode? Mean for symmetric data; median when outliers or skew (incomes); mode for categories.
What does standard deviation tell you? The typical distance of values from the mean, in the same units.
What is a p-value? If there were truly no effect, the chance of seeing a result at least this extreme. It is not the chance that the hypothesis is true.
What is a confidence interval? A range built so that, over many repeats, about 95 percent of such ranges contain the true value.
Type I versus type II error? Type I: false alarm (reject a true null). Type II: miss (keep a false null). Power = 1 - type II rate.
Correlation versus causation? Two things moving together does not mean one causes the other; a third factor or chance may explain it.
Why does sample size matter? Larger samples give narrower intervals and more power; they do not fix bias.

Show you can use the ideas: a confidence interval and a test on seeded synthetic data.

from scipy import stats
rng = np.random.default_rng(1)
a = rng.normal(100, 20, 200)          # loan sizes, group A
b = rng.normal(108, 20, 200)          # group B
lo, hi = stats.t.interval(0.95, len(a) - 1, loc=a.mean(), scale=stats.sem(a))
t, p = stats.ttest_ind(a, b, equal_var=False)
print(f"95% CI for A mean: {lo:.1f} to {hi:.1f}")
print(f"difference p-value: {p:.4f}  (below 0.05: {p < 0.05})")

95% CI for A mean: 95.9 to 101.1
difference p-value: 0.0000  (below 0.05: True)

The base-rate question is a common trap: a fraud rule catches 90 percent of fraud and wrongly flags 5 percent of honest cases, and 1 percent of cases are fraud. What share of flags is real?

sens, fpr, prev = 0.90, 0.05, 0.01
ppv = sens * prev / (sens * prev + fpr * (1 - prev))
print(f"share of flagged cases that are real fraud: {ppv:.1%}")

share of flagged cases that are real fraud: 15.4%

Say: even a good rule produces mostly false alarms when the event is rare, so I would pair it with review capacity and track precision and recall.

#21.6 Machine learning questions (Parts 9 to 13)

Question Model answer
Supervised versus unsupervised? Supervised learns from known answers (predict default). Unsupervised has none and finds structure (segments).
What is overfitting and how do you fight it? The model memorises noise: great on training, poor on new data. Use more data, simpler models, regularisation, early stopping, cross-validation.
Bias versus variance? Bias: too simple, misses the pattern. Variance: too flexible, chases noise. Tune complexity to balance them.
What is data leakage? Information in training that would not exist at prediction time (future data, a post-outcome field, scaling before the split). It inflates scores.
Accuracy, precision, recall, F1? Accuracy: share right. Precision: of predicted positives, share real. Recall: of real positives, share caught. F1: their balance.
How do you handle imbalanced classes? Judge by recall, precision, PR-AUC; use class weights, resampling or a tuned threshold; keep test data untouched.
What is regularisation? A penalty on large coefficients: L2 (Ridge) shrinks them, L1 (Lasso) can set some to zero.
How do you choose an algorithm? Start with a simple baseline, then trees or boosting for tabular data. Weigh accuracy, speed, explainability and the cost of mistakes.
Why use cross-validation? It uses every row for both training and testing, giving a steadier estimate.
Random forest versus boosting? Forest: many independent deep trees averaged (stable). Boosting: shallow trees built one after another, each fixing the last (often more accurate, needs tuning).

Make the answers concrete. This cell shows overfitting, a baseline and leakage in a few lines.

from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier
from sklearn.dummy import DummyClassifier

X, y = load_breast_cancer(return_X_y=True)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.3, stratify=y, random_state=42)
base = DummyClassifier(strategy="most_frequent").fit(X_tr, y_tr)
tree = DecisionTreeClassifier(random_state=42).fit(X_tr, y_tr)
print("baseline test accuracy :", round(base.score(X_te, y_te), 3))
print("deep tree train / test :", round(tree.score(X_tr, y_tr), 3), "/", round(tree.score(X_te, y_te), 3))

baseline test accuracy : 0.626
deep tree train / test : 1.0 / 0.918

Read the report aloud in an interview: precision and recall per class, and what a mistake costs. For a lender, missing a defaulter (low recall) and rejecting a good customer (low precision) have different costs.

Leakage. Putting the scaler inside a Pipeline means it is fitted on training rows only. Scaling the whole dataset first lets test information leak into training. Interviewers often ask for this exact example.

#21.7 Deep learning and LLM basics (Parts 14, 16)

Question Model answer
What is a neural network? Layers of simple units; each takes weighted inputs, adds a bias and applies a non-linear activation.
Why an activation function? Without it, stacked layers collapse into one linear model.
What does training do? Predict, measure the loss, use backpropagation to get gradients, update weights with gradient descent; repeat.
Epoch, batch, learning rate? Epoch: one pass over the data. Batch: rows per update. Learning rate: size of each weight step.
How do you stop a network overfitting? Early stopping on a validation set, dropout, weight decay, more data, smaller network.
When is deep learning not the answer? Small tabular data: boosted trees are usually as good, faster and easier to explain.
What is an LLM? A very large neural network trained to predict the next token in text; with prompts it can answer, summarise and write code.
What is a hallucination? A fluent answer that is wrong or invented. Check facts against trusted sources.
What is retrieval-augmented generation (RAG)? Look up relevant documents first and put them in the prompt, so answers rest on your own data.

A one-neuron computation you can explain on a whiteboard: weighted sum, bias, activation.

x = np.array([0.5, 2.0])           # inputs
w = np.array([1.5, -0.4])          # weights
b = 0.1                            # bias
z = x @ w + b
relu = max(z, 0.0)
sigmoid = 1 / (1 + np.exp(-z))
print("z =", round(z, 2), "| relu =", round(relu, 2), "| sigmoid =", round(sigmoid, 3))

z = 0.05 | relu = 0.05 | sigmoid = 0.512

Responsible use. When using an AI assistant for analysis, give it the schema and a sample, ask for code you can read, run it yourself, and never paste personal customer data into a public tool.

#21.8 Scenario questions for a Kenyan lender (credit-risk analyst)

Credit-risk roles at digital lenders, banks and SACCOs ask about the metrics and data problems of a loan book. Definitions and thresholds here are illustrative; use your employer's policy and the regulator's current rules.

Question Model answer
PD, LGD, EAD? Probability of default, loss given default (share lost after recoveries), exposure at default. Expected loss = PD x LGD x EAD.
PAR30 and PAR90? Outstanding balance of loans over 30 (or 90) days past due, as a share of the total outstanding portfolio.
Roll rate? Share of balances moving to the next worse delinquency bucket in a period.
Vintage analysis? Default rate by disbursement month against loan age, so cohorts compare fairly.
Right-censoring? Recent loans have had no time to default, so their rate looks low. Compare cohorts at the same age.
Why not accuracy? Defaults are rare; predicting nobody defaults looks accurate. Use AUC, KS, recall.
AUC, Gini, KS? AUC: chance a random bad scores worse than a random good. Gini = 2 x AUC - 1. KS: largest gap between the good and bad cumulative distributions.
Missing income? Do not set it to zero. Flag it, study its link with default, impute with a reason.
Explaining a rejection? Name the main drivers in plain language and check fairness across groups and counties.

Compute the core metrics yourself on a small synthetic loan book.

book = pd.DataFrame({
    "outstanding": [50_000, 80_000, 20_000, 120_000, 30_000, 60_000, 45_000, 90_000, 25_000, 70_000],
    "dpd": [0, 0, 35, 0, 95, 10, 0, 62, 0, 120],
    "pd": [0.02, 0.03, 0.35, 0.02, 0.9, 0.08, 0.03, 0.5, 0.02, 0.95],
})
lgd = 0.6
total = book["outstanding"].sum()
par30 = book.loc[book["dpd"] > 30, "outstanding"].sum() / total
par90 = book.loc[book["dpd"] > 90, "outstanding"].sum() / total
el = (book["pd"] * lgd * book["outstanding"]).sum()
print(f"PAR30 {par30:.1%} | PAR90 {par90:.1%} | expected loss Ksh {el:,.0f} ({el / total:.1%} of book)")

PAR30 35.6% | PAR90 16.9% | expected loss Ksh 94,770 (16.1% of book)
from sklearn.metrics import roc_auc_score
from scipy.stats import ks_2samp

rng = np.random.default_rng(14)
bad, good = rng.normal(0.62, 0.15, 300), rng.normal(0.40, 0.15, 1700)
yv, score = np.r_[np.ones(300), np.zeros(1700)], np.r_[bad, good]
auc = roc_auc_score(yv, score)
print(f"AUC {auc:.3f} | Gini {2 * auc - 1:.3f} | KS {ks_2samp(bad, good).statistic:.3f}")

#Scenario: the approval rate fell

Question. Approvals dropped from one month to the next. What do you do? Model answer. First confirm the number (same definition, same period, no missing data). Then split it: by channel, county, product, new versus returning customers, and by score band. Check for a policy or model change, a data feed problem, or a shift in who applies. Report what you found, what you could not rule out, and propose one next check.

#Scenario: a new model looks too good

Question. A default model shows near-perfect AUC. Model answer. Suspect leakage first: a field recorded after disbursement (days past due, collections status), or random splitting of data from the same customer. Rebuild with only application-time fields, split by time, and expect a lower but honest score.

#Scenario: choose a cut-off

Question. How do you pick a score cut-off? Model answer. The cut-off trades approvals against losses. Estimate for each cut-off the expected profit: interest earned on good loans minus losses on bad ones. Choose where that is highest within risk appetite, then monitor stability monthly.

rng = np.random.default_rng(3)
n = 2000
risk = rng.beta(2, 5, n)                          # synthetic default probability
bad_flag = rng.random(n) < risk
principal, margin, lgd = 30_000, 0.12, 0.6
rows = []
for cut in [0.15, 0.25, 0.35, 0.50, 1.01]:
    take = risk < cut                              # approve if risk below cut-off
    profit = (take & ~bad_flag).sum() * principal * margin - (take & bad_flag).sum() * principal * lgd
    rows.append((cut, int(take.sum()), int(profit)))
pd.DataFrame(rows, columns=["cutoff", "approved", "profit_ksh"])
cutoff approved profit_ksh
0 0.15 455 903600
1 0.25 949 500400
2 0.35 1392 -885600
3 0.50 1772 -3060000
4 1.01 2000 -5090400

In this synthetic example, approving everyone loses money, and profit falls as you let in riskier applicants. The strictest cut-off earns most here, but it approves few people, so a real choice also weighs volume, growth and risk appetite.

#21.9 Behavioural questions and the STAR method

STAR = Situation, Task, Action, Result. Two sentences of context, then spend most of the time on your action, then a result with a number or a lesson. Only tell true stories from your own work, studies or portfolio projects; prepare four that you can adapt.

Question What they look for Prepare
Tell me about a project you are proud of. Ownership and impact A portfolio project with a clear finding
Describe a time your data was wrong or messy. Care and method How you found it and fixed it
Tell me about explaining numbers to a non-technical person. Communication A chart and a plain sentence
When did you disagree with a colleague? Teamwork Facts first, a respectful outcome
Describe a mistake you made. Honesty and learning What you changed afterwards
How do you prioritise several urgent requests? Judgement Impact, deadline, ask the requester

STAR shape. S: Our weekly report showed a sudden jump in repayments. T: I had to confirm it before it reached management. A: I checked the join and found duplicate payment rows from a re-sent file, removed the duplicates, and added a row-count check. R: The corrected figure was lower, the report went out on time, and the check now runs every week. (Example shape only: replace it with your own true story.)

#Questions to ask them

  • Which data sources does the team use, and how clean are they?
  • How are models or reports checked before people act on them?
  • What would a strong first three months look like?
  • How do analysts and the business teams work together?

#21.10 Interview day checklist

  • Before: reread the job advert, list its tools (SQL, Power BI, Python), and match one project to each.
  • Prepare a one-minute introduction: who you are, what you built, what you want next.
  • Have your GitHub portfolio open and one finding you can explain in two minutes.
  • In a coding test: restate the task, handle missing data, check row counts, and say what you would verify.
  • If you are stuck: think aloud, solve a smaller version, and ask a clarifying question.
  • After: send a short thank-you note and write down the questions you struggled with.
Key takeaways
  • Answer with definition, example and caution; keep it to about thirty seconds.
  • Know the traps: duplicated joins, leakage, base rates, accuracy on rare events.
  • Show a number: small runnable code beats a long explanation.
  • For credit risk, be fluent in PD, LGD, EAD, PAR, vintages and why accuracy misleads.
  • Use STAR with true stories, and spend most of the time on your own action.
  • Say 'I would check' and name the check.
