#12.1 Why Combine Models? Bagging

A single decision tree (Part 11) is easy to read but unstable: change a few rows and the tree changes. An ensemble combines many models so their individual errors cancel out. There are three main recipes: bagging (train models independently on different samples and average them), boosting (train models one after another, each fixing the last one's mistakes) and stacking (let a final model learn how to blend them).

Throughout this Part we use one running example: a synthetic table of 3,000 loan applications at an imaginary lender (made up with a fixed seed; no real people). The target default is 1 when the borrower defaults. The signal includes curves and interactions, which is where tree ensembles beat straight-line models.

import numpy as np, pandas as pd
import matplotlib.pyplot as plt

def make_loans(n, seed):
    rng = np.random.default_rng(seed)
    df = pd.DataFrame({
        "age": rng.integers(21, 65, n),
        "income_ksh": rng.lognormal(10.9, 0.5, n).round(-2),
        "loan_ksh": rng.lognormal(10.0, 0.6, n).round(-2),
        "term_months": rng.choice([3, 6, 12, 24], n),
        "prior_late": rng.poisson(0.8, n),
        "debt_ratio": rng.beta(2, 5, n).round(3),
        "county": rng.choice(["Nairobi", "Mombasa", "Kisumu", "Nakuru", "Eldoret"], n,
                             p=[.4, .2, .15, .15, .1]),
        "occupation": rng.choice(["salaried", "trader", "farmer", "boda rider"], n,
                                 p=[.35, .3, .2, .15]),
        "application_date": pd.Timestamp("2024-01-01")
                            + pd.to_timedelta(rng.integers(0, 540, n), unit="D"),
        "note": rng.choice(["salary delayed by employer", "stable monthly salary",
                            "new business with stock on credit", "school fees due this term",
                            "harvest expected next month", "no comment"], n)})
    z = (-3.2 + 1.2 * df.debt_ratio + 0.25 * df.prior_late
         + 2.2 * (df.loan_ksh / df.income_ksh > 0.8)
         + 2.2 * ((df.debt_ratio > 0.4) & (df.prior_late >= 2))
         + 1.3 * ((df.age < 27) | (df.age > 58)) + 0.5 * (df.term_months == 24)
         + 0.4 * (df.occupation == "boda rider") + 0.9 * (df.note == "salary delayed by employer")
         + 0.6 * (df.application_date.dt.month == 12))
    df["default"] = (rng.random(n) < 1 / (1 + np.exp(-z))).astype(int)
    return df

loans = make_loans(3000, seed=11)
print("synthetic data; default rate:", round(loans["default"].mean(), 3))
loans[["age", "income_ksh", "loan_ksh", "prior_late", "debt_ratio", "county", "default"]].head(4)

from sklearn.model_selection import train_test_split
from sklearn.metrics import roc_auc_score
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

num = ["age", "income_ksh", "loan_ksh", "term_months", "prior_late", "debt_ratio"]
X, y = loans[num], loans["default"]
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.25, stratify=y, random_state=42)
results = {}                      # model name -> test AUC, filled as we go

def evaluate(name, model):
    model.fit(X_tr, y_tr)
    results[name] = round(roc_auc_score(y_te, model.predict_proba(X_te)[:, 1]), 3)
    return results[name]

print("logistic regression AUC:", evaluate("logistic", make_pipeline(StandardScaler(),
                                           LogisticRegression(max_iter=1000))))

logistic regression AUC: 0.721

What bagging does. Bagging is short for bootstrap aggregating. A bootstrap sample draws rows with replacement until it is as big as the original, so some rows appear twice and some not at all.

rng = np.random.default_rng(0)
rows = rng.integers(0, len(X_tr), len(X_tr))          # one bootstrap sample of row positions
print("share of distinct rows in a bootstrap sample:", round(len(np.unique(rows)) / len(X_tr), 3))

share of distinct rows in a bootstrap sample: 0.625

About two thirds of the rows make it into each sample. The rows left out are the out-of-bag (OOB) rows, a free validation set for each model. Bagging fits one tree per sample and averages their votes.

from sklearn.tree import DecisionTreeClassifier
from sklearn.ensemble import BaggingClassifier

tree = DecisionTreeClassifier(random_state=42)
bag = BaggingClassifier(DecisionTreeClassifier(random_state=42), n_estimators=50,
                        random_state=42, n_jobs=2)
print("single full tree AUC:", evaluate("tree", tree))
print("50 bagged trees AUC :", evaluate("bagging", bag))

single full tree AUC: 0.621
50 bagged trees AUC : 0.746

Averaging removes the random wobble of individual deep trees, so the bagged ensemble ranks borrowers far better than one tree. This works because each deep tree has low bias but high variance; averaging cuts variance without raising bias.

#12.2 Random Forest and Extra Trees

What it does. A random forest is bagging for trees with one extra trick: at each split a tree may only look at a random subset of features (max_features). That makes the trees less alike, so averaging them helps more.

How it works. Grow many deep trees on bootstrap samples, each split choosing the best feature among a random few, then average the predicted probabilities. Extra trees (extremely randomised trees) go further: they also pick the cut-off at random and usually skip bootstrapping. That is faster and sometimes smoother.

  • Works best when you want a strong model with little tuning, mixed feature types, no scaling, and some robustness to noise and outliers.
  • Struggles when you need a tiny, readable model, or the signal needs extrapolation beyond the training range (forests cannot predict outside what they saw).
  • Key settings: n_estimators (more is rarely worse, just slower), max_depth, min_samples_leaf, max_features, class_weight, oob_score.
from sklearn.ensemble import RandomForestClassifier, ExtraTreesClassifier

rf = RandomForestClassifier(n_estimators=150, min_samples_leaf=5, oob_score=True,
                            n_jobs=2, random_state=42)
et = ExtraTreesClassifier(n_estimators=150, min_samples_leaf=5, n_jobs=2, random_state=42)
print("random forest AUC:", evaluate("random forest", rf))
print("OOB accuracy     :", round(rf.oob_score_, 3), "(free estimate, no test set used)")
print("extra trees AUC  :", evaluate("extra trees", et))

random forest AUC: 0.763
OOB accuracy     : 0.779 (free estimate, no test set used)
extra trees AUC  : 0.772

min_samples_leaf=5 stops trees from memorising single borrowers. The OOB accuracy is computed from rows each tree never saw, so it is an honest estimate you get for free.

imp = pd.Series(rf.feature_importances_, index=num).sort_values(ascending=False)
print(imp.round(3))

#12.3 Boosting: AdaBoost and Gradient Boosting

What it does. Boosting builds a strong model from many weak learners (very small trees), one at a time, each concentrating on what the earlier ones got wrong.

How it works. AdaBoost raises the weight of misclassified rows, so the next small tree must pay attention to them, and finally combines trees with votes weighted by accuracy. Gradient boosting starts from a simple guess, measures the remaining errors (the gradient of the loss) and fits the next small tree to those errors, adding it with a small step size (learning_rate). Trees are added until the error stops falling.

  • Works best when you want top accuracy on tabular data and can tune a little.
  • Struggles when the data is very noisy (it can chase noise) or you add too many trees without a stopping rule.
  • Key settings: n_estimators, learning_rate (smaller needs more trees), max_depth (keep small, 2 to 5), subsample.
from sklearn.ensemble import AdaBoostClassifier, GradientBoostingClassifier
from sklearn.metrics import log_loss

ada = AdaBoostClassifier(n_estimators=100, learning_rate=0.5, random_state=42)
gb = GradientBoostingClassifier(n_estimators=150, learning_rate=0.1, max_depth=3,
                                random_state=42)
print("AdaBoost AUC          :", evaluate("AdaBoost", ada))
print("gradient boosting AUC :", evaluate("gradient boosting", gb))

AdaBoost AUC          : 0.747
gradient boosting AUC : 0.766

Boosting overfits if you let it run too long. staged_predict_proba gives the predictions after each tree, so we can watch training and test loss as trees are added.

BLUE, GREEN, GREY, DARK, AMBER = "#1F5FD6", "#2BB38A", "#9CA3AF", "#0B2A4A", "#B45309"
fast = GradientBoostingClassifier(n_estimators=200, learning_rate=0.2, max_depth=3,
                                  random_state=42).fit(X_tr, y_tr)
tr_loss = [log_loss(y_tr, p) for p in fast.staged_predict_proba(X_tr)]
te_loss = [log_loss(y_te, p) for p in fast.staged_predict_proba(X_te)]
best = int(np.argmin(te_loss)) + 1
fig, ax = plt.subplots(figsize=(10, 3.6))
ax.plot(range(1, 201), tr_loss, color=BLUE, label="training loss")
ax.plot(range(1, 201), te_loss, color=GREEN, label="test loss")
ax.axvline(best, color=AMBER, ls="--", label=f"best at {best} trees")
ax.set(title="Gradient boosting: loss as trees are added (synthetic loans)",
       xlabel="Number of trees", ylabel="Log loss (lower is better)")
ax.legend()
plt.tight_layout(); plt.savefig("p12_boosting.png", dpi=130); plt.close()
print("saved p12_boosting.png; lowest test loss at", best, "trees")

saved p12_boosting.png; lowest test loss at 45 trees

Training loss keeps falling, but test loss reaches a minimum and then climbs: the extra trees are fitting noise. The cure is early stopping: stop when a validation score stops improving (next section), or lower the learning rate and tune the tree count.

#12.4 HistGradientBoosting, XGBoost and LightGBM

Plain gradient boosting is slow on big data. Three modern libraries make it fast by sorting each feature into about 255 histogram bins first, so it tests a few hundred cut-offs instead of thousands. They are the usual winners on tabular data.

  • HistGradientBoostingClassifier (scikit-learn): no extra install, handles missing values and categorical columns, built-in early stopping.
  • XGBoost: the well-known library; strong regularisation options; fast on CPUs.
  • LightGBM: grows trees leaf by leaf (num_leaves), often the fastest on large data.
from sklearn.ensemble import HistGradientBoostingClassifier
from xgboost import XGBClassifier
from lightgbm import LGBMClassifier

X_fit, X_val, y_fit, y_val = train_test_split(X_tr, y_tr, test_size=0.2, stratify=y_tr,
                                              random_state=42)
hgb = HistGradientBoostingClassifier(max_iter=300, learning_rate=0.05, max_depth=3,
                                     early_stopping=True, random_state=42)
xgb = XGBClassifier(n_estimators=300, learning_rate=0.05, max_depth=3, subsample=0.8,
                    early_stopping_rounds=20, eval_metric="logloss", n_jobs=2, random_state=42)
xgb.fit(X_fit, y_fit, eval_set=[(X_val, y_val)], verbose=False)
results["XGBoost"] = round(roc_auc_score(y_te, xgb.predict_proba(X_te)[:, 1]), 3)
print("HistGradientBoosting AUC:", evaluate("HistGradientBoosting", hgb), "| trees:", hgb.n_iter_)
print("XGBoost AUC             :", results["XGBoost"], "| best round:", xgb.best_iteration)

HistGradientBoosting AUC: 0.763 | trees: 89
XGBoost AUC             : 0.769 | best round: 98
import warnings
import lightgbm as lgb
warnings.filterwarnings("ignore")      # hides a library deprecation notice

lgbm = LGBMClassifier(n_estimators=300, learning_rate=0.05, num_leaves=8, min_child_samples=30,
                      subsample=0.8, subsample_freq=1, n_jobs=2, random_state=42, verbose=-1)
lgbm.fit(X_fit, y_fit, eval_set=[(X_val, y_val)], eval_metric="auc",
         callbacks=[lgb.early_stopping(20, verbose=False)])
results["LightGBM"] = round(roc_auc_score(y_te, lgbm.predict_proba(X_te)[:, 1]), 3)
print("LightGBM AUC:", results["LightGBM"], "| best round:", lgbm.best_iteration_)

LightGBM AUC: 0.765 | best round: 46

All three follow the same fit/predict_proba pattern as every scikit-learn model, so they drop into pipelines and searches. Early stopping needs a validation set that is separate from the final test set.

Rule of thumb. Boosting libraries have many settings. A safe recipe: learning rate 0.03 to 0.1, tree depth 3 to 6 (or num_leaves 8 to 31), row sampling 0.7 to 0.9, many trees, and early stopping to pick the count. Tune depth and min_child_samples first.

#12.5 Voting and Stacking

Voting averages the predictions of different kinds of model. Stacking goes further: the base models' predictions become the inputs of a final model (the meta-learner), which learns how much to trust each. The base predictions are made out-of-fold (cv=) so the meta-learner never sees predictions made on rows the base model trained on.

from sklearn.ensemble import VotingClassifier, StackingClassifier

base = [("logit", make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))),
        ("forest", RandomForestClassifier(n_estimators=100, min_samples_leaf=5, n_jobs=2,
                                          random_state=42)),
        ("hgb", HistGradientBoostingClassifier(max_iter=100, learning_rate=0.1, max_depth=3,
                                               random_state=42))]
vote = VotingClassifier(base, voting="soft")
stack = StackingClassifier(base, final_estimator=LogisticRegression(), cv=3)
print("soft voting AUC:", evaluate("voting", vote))
print("stacking AUC   :", evaluate("stacking", stack))

soft voting AUC: 0.774
stacking AUC   : 0.772
order = pd.Series(results).sort_values()
fig, ax = plt.subplots(figsize=(10, 3.8))
colors = [AMBER if k == order.index[-1] else BLUE for k in order.index]

ax.set_xlim(order.min() - 0.03, order.max() + 0.02)

Tree ensembles clearly beat the single tree. The top few models differ by small amounts that one test split cannot separate reliably. Use cross-validation (next section) before declaring a winner, and weigh the extra cost of stacking against its small gain.

Practical view. A stacked model is hard to explain, slow to retrain and has more parts to break. In production, a single well-tuned boosted model is usually the better trade.

#12.6 Cross-Validation Strategies

Cross-validation (CV) repeats train-and-test on several different splits and averages the score (Part 9). The way you split must match how the model will be used.

  • KFold: random folds. Fine for balanced, independent rows.
  • StratifiedKFold: keeps the class mix equal in each fold. Use it for classification, especially with rare positives.
  • TimeSeriesSplit: trains on the past, tests on the future. Use it whenever time matters (loans, sales, fraud).
  • GroupKFold: keeps all rows of one group (one customer, one branch) in the same fold.
from sklearn.model_selection import KFold, StratifiedKFold

for cv in [KFold(5, shuffle=True, random_state=0),
           StratifiedKFold(5, shuffle=True, random_state=0)]:
    rates = [round(float(y.iloc[te].mean()), 3) for _, te in cv.split(X, y)]
    print(type(cv).__name__.ljust(16), "default rate per fold:", rates)

KFold            default rate per fold: [0.255, 0.255, 0.232, 0.253, 0.242]
StratifiedKFold  default rate per fold: [0.248, 0.248, 0.247, 0.247, 0.247]

Stratification keeps each fold's default rate close to the overall rate. Now the time-aware split: sort by application date so each fold trains on earlier applications and tests on later ones.

from sklearn.model_selection import TimeSeriesSplit, cross_val_score

ordered = loans.sort_values("application_date").reset_index(drop=True)
Xo, yo = ordered[num], ordered["default"]
model = HistGradientBoostingClassifier(max_iter=100, learning_rate=0.1, max_depth=3,
                                       random_state=42)
for i, (tr, te) in enumerate(TimeSeriesSplit(n_splits=3).split(Xo)):
    print(f"fold {i}: train {ordered.application_date[tr[0]].date()} to "
          f"{ordered.application_date[tr[-1]].date()} | test "
          f"{ordered.application_date[te[0]].date()} to {ordered.application_date[te[-1]].date()}")
print("time-split AUC  :", cross_val_score(model, Xo, yo, cv=TimeSeriesSplit(3),
                                           scoring="roc_auc").mean().round(3))
print("random-fold AUC :", cross_val_score(model, Xo, yo, cv=StratifiedKFold(3, shuffle=True,
                           random_state=0), scoring="roc_auc").mean().round(3))

fold 0: train 2024-01-01 to 2024-05-12 | test 2024-05-12 to 2024-09-25
fold 1: train 2024-01-01 to 2024-09-25 | test 2024-09-25 to 2025-02-07
fold 2: train 2024-01-01 to 2025-02-07 | test 2025-02-08 to 2025-06-23
time-split AUC  : 0.743
random-fold AUC : 0.753

Here the two scores are close because this synthetic data has no strong drift. In real lending data, behaviour drifts over time and the random-fold score is usually the optimistic one, which is why the time-aware split is the honest test.

Common mistake. Randomly shuffled folds let a model train on March applications and be tested on February ones, which is impossible in real life. For anything that happens over time, split by time.

#12.7 Hyperparameter Tuning: Grid Search and Random Search

Hyperparameters are settings you choose before training (tree depth, number of trees, C). Parameters are what the model learns (tree splits, weights). GridSearchCV tries every combination in a grid with cross-validation. RandomizedSearchCV samples a fixed number of random combinations: it handles many settings and wide ranges far better when the grid would be huge.

from sklearn.model_selection import GridSearchCV, StratifiedKFold

cv3 = StratifiedKFold(3, shuffle=True, random_state=42)
grid = GridSearchCV(
    RandomForestClassifier(n_estimators=60, n_jobs=2, random_state=42),
    param_grid={"max_depth": [3, 6, None], "min_samples_leaf": [3, 10, 30]},
    scoring="roc_auc", cv=cv3)
grid.fit(X_tr, y_tr)
print("best settings :", grid.best_params_)
print("best CV AUC   :", round(grid.best_score_, 3))
print("test AUC      :", round(roc_auc_score(y_te, grid.predict_proba(X_te)[:, 1]), 3))

best settings : {'max_depth': None, 'min_samples_leaf': 10}
best CV AUC   : 0.759
test AUC      : 0.757

GridSearchCV refits the best combination on all training data, so grid itself is ready to predict. The 9 combinations times 3 folds meant 27 fits. Add one more setting with 4 values and it becomes 108, which is when random search pays off.

from scipy.stats import randint, loguniform
from sklearn.model_selection import RandomizedSearchCV

rand = RandomizedSearchCV(
    HistGradientBoostingClassifier(max_iter=100, random_state=42),
    param_distributions={"learning_rate": loguniform(0.02, 0.3),
                         "max_depth": randint(2, 6),
                         "min_samples_leaf": randint(10, 80),
                         "l2_regularization": loguniform(1e-3, 10)},
    n_iter=8, scoring="roc_auc", cv=cv3, random_state=42, n_jobs=1)
rand.fit(X_tr, y_tr)
floats = ("learning_rate", "l2_regularization")
print({k: (round(float(v), 3) if k in floats else int(v))
       for k, v in rand.best_params_.items()})
print("best CV AUC:", round(rand.best_score_, 3),
      "| test AUC:", round(roc_auc_score(y_te, rand.predict_proba(X_te)[:, 1]), 3))

{'l2_regularization': 0.016, 'learning_rate': 0.083, 'max_depth': 5, 'min_samples_leaf': 58}
best CV AUC: 0.76 | test AUC: 0.77

Common mistake. The best CV score is slightly optimistic, because you picked the winner out of many tries on the same folds. Keep the test set untouched until the very end, and report the test score. For an unbiased estimate of the whole tuning procedure use nested CV (a search inside cross_val_score).

#12.8 Feature Engineering

Feature engineering means turning raw columns into inputs that make the pattern easier to learn. Good features often beat a fancier algorithm. We work on the full loans table, including county, occupation, the application date and a free-text note.

#Scaling and encoding

Linear models, k-NN and SVMs need scaling: StandardScaler (mean 0, spread 1) or MinMaxScaler (0 to 1). Tree models do not care. Text categories must become numbers: one-hot encoding makes a 0/1 column per category (right for unordered categories such as county); ordinal encoding maps ordered categories to 0, 1, 2.

from sklearn.preprocessing import OneHotEncoder, MinMaxScaler

demo = loans[["county", "income_ksh"]].head(4)

                   index=demo.county).astype(int).to_string())

#Binning, ratios, interactions and dates

Binning turns a number into ranges, useful when risk changes in steps. A ratio or interaction combines columns when only the combination matters (loan size relative to income). Date features extract month, day of week and so on, because models cannot read a raw date.

def engineer(d):
    out = d.copy()
    out["loan_to_income"] = out.loan_ksh / out.income_ksh          # ratio
    out["debt_x_late"] = out.debt_ratio * out.prior_late          # interaction
    out["age_band"] = pd.cut(out.age, [20, 30, 40, 50, 65],
                             labels=["21-30", "31-40", "41-50", "51-64"]).astype(str)
    out["month"] = out.application_date.dt.month                 # date features
    out["weekday"] = out.application_date.dt.dayofweek
    out["is_december"] = (out.month == 12).astype(int)
    return out.drop(columns="application_date")

feat = engineer(loans)
print(feat[["loan_to_income", "debt_x_late", "age_band", "month", "weekday"]].head(4))

2        0.416409        0.273    51-64      9        6
3        0.686869        0.000    41-50      1        4

These steps use each row on its own, so they cannot leak information between train and test. Steps that learn something from the data (a scaler's mean, an encoder's category list) belong inside a Pipeline (12.9).

#Text: a first look at TF-IDF

A model needs numbers, so text is turned into a table with one column per word. TF-IDF (term frequency times inverse document frequency) scores a word highly when it appears often in one note but rarely across all notes, so common filler words count for little.

from sklearn.feature_extraction.text import TfidfVectorizer

tf = TfidfVectorizer(ngram_range=(1, 2), min_df=20)
M = tf.fit_transform(loans["note"])
print("matrix shape (notes x terms):", M.shape)
tf_lr = LogisticRegression(max_iter=1000).fit(M, loans["default"])
w = pd.Series(tf_lr.coef_[0], index=tf.get_feature_names_out()).sort_values()
print("words that raise default risk:", list(w.index[-3:][::-1]))
print("words that lower default risk:", list(w.index[:3]))

matrix shape (notes x terms): (3000, 41)
words that raise default risk: ['salary delayed', 'by employer', 'by']
words that lower default risk: ['monthly', 'monthly salary', 'stable monthly']

Real text work needs cleaning, larger vocabularies and often word embeddings (Part 16). TF-IDF with a linear model is still a strong, quick baseline.

#12.9 Leak-Free Pipelines

A data leak happens when information from the test rows influences training. The most common cause is fitting a scaler, encoder, imputer or feature selector on all the data before splitting. A Pipeline fits every step on the training folds only, every time. A ColumnTransformer applies different steps to different columns.

from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline
from sklearn.model_selection import cross_val_score

Xf, yf = feat.drop(columns="default"), feat["default"]
Xf_tr, Xf_te, yf_tr, yf_te = train_test_split(Xf, yf, test_size=0.25, stratify=yf, random_state=42)
numeric = ["age", "income_ksh", "loan_ksh", "term_months", "prior_late", "debt_ratio",
           "loan_to_income", "debt_x_late", "month", "weekday", "is_december"]
pre = ColumnTransformer([
    ("num", StandardScaler(), numeric),
    ("cat", OneHotEncoder(handle_unknown="ignore"), ["county", "occupation", "age_band"]),
    ("txt", TfidfVectorizer(min_df=20), "note")], sparse_threshold=0)
lr_pipe = Pipeline([("prep", pre), ("model", LogisticRegression(max_iter=1000))])
hgb_pipe = Pipeline([("prep", pre), ("model", HistGradientBoostingClassifier(
    max_iter=100, learning_rate=0.1, max_depth=3, random_state=42))])
pipes = [("logistic + engineered features", lr_pipe), ("HGB + engineered features", hgb_pipe)]
for name, p in pipes:
    s = cross_val_score(p, Xf_tr, yf_tr, cv=cv3, scoring="roc_auc")
    print(name.ljust(32), "CV AUC:", s.mean().round(3))

logistic + engineered features   CV AUC: 0.738
HGB + engineered features        CV AUC: 0.775

Compare with the numeric-only models earlier in this Part: the engineered columns and note words help the straight-line model a little and the boosted model more, because ratios, dates and text add information that was not in the six raw numbers.

hgb_pipe.fit(Xf_tr, yf_tr)
print("held-out test AUC (HGB pipeline):",
      round(roc_auc_score(yf_te, hgb_pipe.predict_proba(Xf_te)[:, 1]), 3))
import joblib
joblib.dump(hgb_pipe, "p12_loan_model.joblib")           # the whole recipe, one file
reloaded = joblib.load("p12_loan_model.joblib")
print("reloaded model predicts the same:",
      bool((reloaded.predict_proba(Xf_te) == hgb_pipe.predict_proba(Xf_te)).all()))

held-out test AUC (HGB pipeline): 0.794
reloaded model predicts the same: True

Saving the entire pipeline means that production applies exactly the same scaling and encoding as training (see Part 18). Now see how big a leak can be. The data below is pure noise: 100 rows, 500 random columns and a random target, so an honest model must score about 0.5.

from sklearn.feature_selection import SelectKBest, f_classif

rng = np.random.default_rng(1)
Xn = rng.normal(size=(100, 500)); yn = rng.integers(0, 2, 100)
cv5 = StratifiedKFold(5, shuffle=True, random_state=0)

picked = SelectKBest(f_classif, k=10).fit_transform(Xn, yn)          # selection saw ALL rows
leaky = cross_val_score(LogisticRegression(), picked, yn, cv=cv5, scoring="roc_auc").mean()
safe_pipe = make_pipeline(SelectKBest(f_classif, k=10), LogisticRegression())
safe = cross_val_score(safe_pipe, Xn, yn, cv=cv5, scoring="roc_auc").mean()
print("selection before CV (leak):", round(leaky, 3))
print("selection inside Pipeline :", round(safe, 3))

selection before CV (leak): 0.875
selection inside Pipeline : 0.505

The leaky version finds a 'pattern' in pure noise, because the selected columns were chosen using the very rows that were later used for testing. The pipeline version correctly reports no skill.

Rule. Whenever a step learns from data (scale, encode, impute, select, balance classes), put it inside the Pipeline and pass the Pipeline to cross_val_score or GridSearchCV.

#12.10 Feature Selection

Feature selection keeps the useful columns and drops the rest. It makes models simpler, faster and sometimes more accurate, and it reduces what you must collect in production. Three families exist: filter methods score each feature on its own; embedded methods (such as L1 regularisation) select while training; wrapper methods such as RFE (recursive feature elimination) repeatedly fit a model and drop the weakest feature. To see them work, we add three columns of pure noise.

from sklearn.feature_selection import SelectKBest, f_classif, RFE

sel = Xf_tr[numeric].copy()
rs = np.random.default_rng(5)
for c in ["noise_a", "noise_b", "noise_c"]:
    sel[c] = rs.normal(size=len(sel))
scaled = pd.DataFrame(StandardScaler().fit_transform(sel), columns=sel.columns)

f_scores = pd.Series(SelectKBest(f_classif, k="all").fit(scaled, yf_tr).scores_, index=sel.columns)
print("filter (F-score), top 5 :", list(f_scores.sort_values(ascending=False).index[:5]))
print("filter, lowest 3        :", list(f_scores.sort_values().index[:3]))

filter (F-score), top 5 : ['loan_to_income', 'debt_x_late', 'loan_ksh', 'income_ksh', 'prior_late']
filter, lowest 3        : ['noise_c', 'weekday', 'noise_b']
l1 = LogisticRegression(l1_ratio=1, C=0.05, solver="liblinear", max_iter=1000).fit(scaled, yf_tr)
zero = [c for c, w in zip(sel.columns, l1.coef_[0]) if w == 0]
print("L1 (lasso) set these weights to exactly zero:", zero)

rfe = RFE(LogisticRegression(max_iter=1000), n_features_to_select=5).fit(scaled, yf_tr)
print("RFE keeps:", list(sel.columns[rfe.support_]))

L1 (lasso) set these weights to exactly zero: ['loan_ksh', 'prior_late', 'month', 'weekday', 'noise_b', 'noise_c']
RFE keeps: ['term_months', 'prior_late', 'loan_to_income', 'debt_x_late', 'noise_a']

Read the results with care. Noise columns tend to sit at the bottom of the filter ranking and L1 zeroes most of them, but L1 also drops real columns that are redundant with others (for example prior_late is largely carried by debt_x_late), and RFE may keep a noise column. L1 is cheap and works inside the model; RFE is slower but accounts for the model. Always confirm a selection with cross-validation instead of trusting one run.

Common mistake. Pick features inside cross-validation (a Pipeline step), never on the full data first (see the leak demo). With many correlated features, selection can be unstable: different folds may keep different columns, which is normal.

#12.11 Explaining Models: Importance and Partial Dependence (Advanced)

Ensembles are accurate but opaque. Three tools open the box. Impurity importance (feature_importances_) is free but biased toward features with many distinct values. Permutation importance shuffles one column of the test data and measures how much the score drops: if shuffling hurts, the model relied on that column. Partial dependence shows how the average prediction changes as one feature moves, others averaged out. We add a useless random ID-like column to test the bias claim.

from sklearn.inspection import permutation_importance

rs = np.random.default_rng(3)
Xi_tr, Xi_te = X_tr.copy(), X_te.copy()
Xi_tr["random_id"] = rs.permutation(len(Xi_tr)); Xi_te["random_id"] = rs.permutation(len(Xi_te))
forest = RandomForestClassifier(n_estimators=150, min_samples_leaf=5, n_jobs=2, random_state=42)
forest.fit(Xi_tr, y_tr)
imp_imp = pd.Series(forest.feature_importances_, index=Xi_tr.columns)
perm = permutation_importance(forest, Xi_te, y_te, scoring="roc_auc", n_repeats=5,
                              random_state=0, n_jobs=1)
imp_perm = pd.Series(perm.importances_mean, index=Xi_tr.columns)
print(pd.DataFrame({"impurity": imp_imp, "permutation": imp_perm}).round(3)
      .sort_values("permutation", ascending=False))

#12.12 Choosing a Tabular Algorithm, and Using It in the Real World

Algorithm Best for Scaling Missing values Tuning effort Explainable
Logistic regression Baseline, scorecards Needed Impute first Low Very
Decision tree Readable rules No Impute first Low Very
Random forest Strong default, little tuning No Impute first Low Medium
Extra trees Fast, smoother forest No Impute first Low Medium
HistGradientBoosting Accurate, no extra install No Native Medium Medium
XGBoost Competitions, big tables No Native Medium to high Medium
LightGBM Very large data, speed No Native Medium to high Medium
Stacking Last bit of accuracy Per model Per model High Low

A practical order of work: (1) a baseline and logistic regression, (2) a random forest as a no-fuss tree benchmark, (3) a boosted model with early stopping, (4) a small random search, (5) engineered features in a Pipeline, and only then (6) stacking if the gain justifies the complexity. Judge every step with the same cross-validation.

Using it in the real world. Data you need: one row per decision with only information known at that moment, plus a clear outcome definition and enough positives (hundreds, ideally thousands). Validate: split by time, keep a final untouched test period, tune inside cross-validation, and report both a ranking metric (AUC) and a business metric (cost at the chosen threshold, Part 11). How it fails: leakage (a column recorded after the outcome), drift (a new loan product or a new mobile-money fee changes behaviour), and over-tuning to one validation set. Monitor: the distribution of each input and of the scores, the realised default rate per score band, and retrain on a schedule. Scenario: a SACCO scoring member loan applications can start with a logistic scorecard its committee understands, then compare a boosted model on later months, and adopt it only if it saves money at the same approval rate. Keep a reason code (top permutation features) for each declined member.

Key takeaways
  • Ensembles average away variance (bagging, forests) or learn from mistakes (boosting).
  • Boosted trees (HistGradientBoosting, XGBoost, LightGBM) are the usual winners on tabular data; use early stopping and small learning rates.
  • Match the CV scheme to reality: stratified for classes, time-based for time, grouped for customers; tune with random search and keep a clean test set.
  • Put every step that learns from data inside a Pipeline to avoid leaks.
  • Good features (ratios, dates, bins, text) often matter more than the algorithm.
  • Use permutation importance and partial dependence to explain what a model relies on.
