Neural Networks and Deep Learning

Build a neural network from one neuron up: by hand in numpy, then with scikit-learn and PyTorch, then images, sequences and autoencoders, and learn when deep learning is worth it.

In this part
  • Explain what a neuron, a layer and a neural network are, in plain words
  • Follow a forward pass, a loss and backpropagation, and write them from scratch in numpy
  • Train networks with scikit-learn (easy route) and PyTorch (full control)
  • Spot overfitting and fight it with weight decay, dropout and early stopping
  • Know what CNNs, LSTMs and autoencoders are for, and when NOT to use deep learning
You need first Parts 9 to 13Time 8 to 12 hours

Deep learning means machine learning with neural networks that have one or more hidden layers. You already know the workflow from Parts 9 to 12: split the data, scale it, fit, score on unseen data. Only the model changes. This Part builds that model step by step, starting with a single neuron you can compute on paper. All data here is public scikit-learn data or small synthetic data, and all networks are tiny so they run on a laptop.

#14.1 One neuron

A neuron is a tiny function. It takes numbers in, multiplies each by a weight (how much that input matters), adds a bias (a starting nudge), and squeezes the total through an activation function. In symbols: output = activation(w1x1 + w2x2 + b). This is almost logistic regression (Part 11): a neuron with a sigmoid activation is logistic regression.

import numpy as np

def sigmoid(z):
    return 1 / (1 + np.exp(-z))

# A toy loan scorer (synthetic): x1 = monthly income in Ksh 10,000s, x2 = number of open loans
x = np.array([4.5, 2.0])
w = np.array([0.8, -1.1])      # more income helps, more open loans hurts
b = 0.5
z = np.dot(w, x) + b           # weighted sum
print("weighted sum z :", round(z, 3))
print("neuron output  :", round(sigmoid(z), 3), "(read as a probability of repaying)")

weighted sum z : 1.9
neuron output  : 0.87 (read as a probability of repaying)

The weights and bias are the parameters. Training means finding values for them so the outputs match the real answers. A neuron can only draw one straight dividing line, so we stack many neurons into layers. The first layer sees the raw inputs, the middle hidden layers build new features from them, and the last layer gives the answer.

#14.2 Activation functions

Without an activation, stacking layers would still give one straight line, because a combination of straight lines is a straight line. The activation adds the bend. The three you need: sigmoid (squeezes to 0..1, used for the final probability of a yes/no answer), tanh (squeezes to -1..1) and ReLU (keeps positive numbers, turns negatives into 0; the default for hidden layers because it is simple and trains fast).

import numpy as np
import matplotlib.pyplot as plt
import seaborn as sns
BLUE, GREEN, GREY, DARK, AMBER = "#1F5FD6", "#2BB38A", "#9CA3AF", "#0B2A4A", "#B45309"

Sigmoid and tanh flatten at the ends; ReLU is flat for negatives and a straight line for positives.

Sigmoid and tanh go flat at the ends, so their slope is almost zero there. That makes learning slow in deep stacks (the vanishing gradient problem), which is one reason ReLU took over for hidden layers.

#14.3 The forward pass

The forward pass pushes one or many rows of data through the layers to get predictions. Each layer is a matrix multiplication plus a bias, then an activation. Watching the shapes is the best way to understand it: 5 rows with 3 features, a hidden layer of 4 neurons and one output.

import numpy as np
rng = np.random.default_rng(42)

X = rng.normal(size=(5, 3))            # 5 rows, 3 features
W1, b1 = rng.normal(size=(3, 4)), np.zeros(4)   # layer 1: 3 inputs -> 4 hidden neurons
W2, b2 = rng.normal(size=(4, 1)), np.zeros(1)   # layer 2: 4 hidden -> 1 output

hidden = np.maximum(0, X @ W1 + b1)    # ReLU
out = 1 / (1 + np.exp(-(hidden @ W2 + b2)))     # sigmoid

print("X", X.shape, "-> hidden", hidden.shape, "-> output", out.shape)
print("predicted probabilities:", out.ravel().round(3))
print("number of parameters   :", W1.size + b1.size + W2.size + b2.size)

X (5, 3) -> hidden (5, 4) -> output (5, 1)
predicted probabilities: [0.516 0.712 0.522 0.857 0.974]
number of parameters   : 21

These random weights give meaningless answers. Learning is the process of nudging those 21 numbers until the answers become good. To nudge them in the right direction we first need a way to score how wrong the network is.

#14.4 Loss functions

A loss function turns 'how wrong are we?' into one number; training tries to make it small. For predicting a number (regression) use mean squared error (MSE), the average of squared mistakes. For yes/no answers use cross-entropy (also called log loss, see Part 11): it punishes a confident wrong answer very hard and a hesitant one gently.

import numpy as np

def mse(y, p):
    return np.mean((y - p) ** 2)

def cross_entropy(y, p, eps=1e-12):
    p = np.clip(p, eps, 1 - eps)
    return -np.mean(y * np.log(p) + (1 - y) * np.log(1 - p))

y = np.array([1, 0, 1, 1])                       # true answers
good = np.array([0.9, 0.1, 0.8, 0.7])            # confident and mostly right
bad = np.array([0.1, 0.9, 0.2, 0.3])             # confident and wrong
vague = np.array([0.5, 0.5, 0.5, 0.5])           # no idea
for name, p in [("good", good), ("vague", vague), ("bad", bad)]:
    print(f"{name:6s} cross-entropy = {cross_entropy(y, p):.3f}")
print("MSE of a price guess, Ksh:", mse(np.array([100, 250]), np.array([110, 230])))

good   cross-entropy = 0.198
vague  cross-entropy = 0.693
bad    cross-entropy = 1.855
MSE of a price guess, Ksh: 250.0

Rule. Use MSE for numbers (rent in Ksh, crop yield) and cross-entropy for classes (default / no default, fraud / not fraud). Picking the loss that matches the question is the first design decision of any network.

#14.5 Gradient descent and backpropagation, from scratch

We want weights that make the loss small. Picture the loss as a hilly landscape and the weights as your position. The gradient is the slope under your feet. Gradient descent takes a small step downhill, again and again. The step size is the learning rate. Here is the whole idea with one weight: learn w in y = w*x from data where the true w is 3.

import numpy as np
x = np.array([1.0, 2.0, 3.0, 4.0])
y = 3.0 * x                      # true relationship: y = 3x
w, lr = 0.0, 0.02
for step in range(1, 31):
    pred = w * x
    grad = np.mean(2 * (pred - y) * x)     # slope of the MSE with respect to w
    w = w - lr * grad                      # step downhill
    if step in (1, 2, 5, 10, 30):
        print(f"step {step:2d}: w = {w:.4f}, loss = {np.mean((w*x - y)**2):.5f}")

step  1: w = 0.9000, loss = 33.07500
step  2: w = 1.5300, loss = 16.20675
step  5: w = 2.4958, loss = 1.90671
step 10: w = 2.9153, loss = 0.05386
step 30: w = 2.9999, loss = 0.00000

Backpropagation is just the chain rule from calculus, applied layer by layer from the output back to the input. It answers: 'how much did each weight contribute to the error?' so every weight gets its own gradient. You will never code it by hand at work, but doing it once removes the mystery. The classic test is XOR: the output is 1 when exactly one input is 1. No single straight line can separate those cases, so a hidden layer is required.

import numpy as np
rng = np.random.default_rng(1)
X = np.array([[0, 0], [0, 1], [1, 0], [1, 1]], dtype=float)
y = np.array([[0], [1], [1], [0]], dtype=float)

W1, b1 = rng.normal(size=(2, 4)), np.zeros((1, 4))
W2, b2 = rng.normal(size=(4, 1)), np.zeros((1, 1))
sig = lambda z: 1 / (1 + np.exp(-z))
lr = 0.5
for epoch in range(1, 5001):
    h = np.tanh(X @ W1 + b1)                 # forward pass
    p = sig(h @ W2 + b2)
    d2 = (p - y) / len(X)                    # backward: error at the output
    dW2, db2 = h.T @ d2, d2.sum(0, keepdims=True)
    d1 = (d2 @ W2.T) * (1 - h ** 2)          # push the error back through tanh
    dW1, db1 = X.T @ d1, d1.sum(0, keepdims=True)
    W1 -= lr * dW1; b1 -= lr * db1           # gradient descent updates
    W2 -= lr * dW2; b2 -= lr * db2
    if epoch in (1, 100, 1000, 5000):
        loss = -np.mean(y * np.log(p) + (1 - y) * np.log(1 - p))
        print(f"epoch {epoch:4d}  loss {loss:.4f}")
print("predictions:", p.ravel().round(2), " targets:", y.ravel())

epoch    1  loss 0.6712
epoch  100  loss 0.1255
epoch 1000  loss 0.0052
epoch 5000  loss 0.0009
predictions: [0. 1. 1. 0.]  targets: [0. 1. 1. 0.]

The loss falls and the four predictions move to the targets: a network with one hidden layer solved a problem a single neuron cannot. That is the whole engine of deep learning; PyTorch automates exactly these gradient calculations.

Watch out. Common mistake: a learning rate that is too big makes the loss bounce or explode; too small and training crawls. If the loss does not go down, try a smaller rate first.

#14.6 The easy route: scikit-learn MLPClassifier

Before PyTorch, note that scikit-learn already has a neural network: MLPClassifier (MLP = multi-layer perceptron, a plain fully connected network). It fits into the same pipeline you know. Neural networks are sensitive to feature scale, so always scale. We use the breast cancer data (569 patients, 30 measurements, benign or malignant) and compare with logistic regression.

from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.neural_network import MLPClassifier
from sklearn.linear_model import LogisticRegression

data = load_breast_cancer()
X_tr, X_te, y_tr, y_te = train_test_split(data.data, data.target, test_size=0.25,
                                          stratify=data.target, random_state=42)
mlp = make_pipeline(StandardScaler(),
                    MLPClassifier(hidden_layer_sizes=(16, 8), max_iter=500, random_state=42))
logit = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))
for name, m in [("Logistic regression", logit), ("MLP (16, 8)", mlp)]:
    m.fit(X_tr, y_tr)
    print(f"{name:20s} test accuracy = {m.score(X_te, y_te):.3f}")

Logistic regression  test accuracy = 0.986
MLP (16, 8)          test accuracy = 0.965

On a small clean table like this the network and the simple model are close. That is a preview of a lesson at the end of this Part: for tabular data, simple models are hard to beat. Key settings of MLPClassifier: hidden_layer_sizes (layers and neurons), alpha (weight-decay strength), learning_rate_init, max_iter and early_stopping=True.

#14.7 PyTorch basics

PyTorch is the main library for deep learning. Its building block is the tensor, a numpy-like array that can also record how it was computed so gradients come for free. Tensors convert to and from numpy easily.

import numpy as np
import torch
torch.manual_seed(42)
torch.set_num_threads(2)

a = torch.tensor([[1.0, 2.0], [3.0, 4.0]])
print("shape:", a.shape, " dtype:", a.dtype)
print("matrix product:\n", a @ a)
print("from numpy:", torch.from_numpy(np.arange(3.0)), " back to numpy:", a.numpy()[0])

shape: torch.Size([2, 2])  dtype: torch.float32
matrix product:
 tensor([[ 7., 10.],
        [15., 22.]])
from numpy: tensor([0., 1., 2.], dtype=torch.float64)  back to numpy: [1. 2.]

Autograd is PyTorch's automatic gradient engine. Mark a tensor with requires_grad=True, compute a result, call .backward(), and the gradient appears. Check it against calculus: for y = w^2 + 3w at w = 2 the slope is 2w + 3 = 7.

import torch
w = torch.tensor(2.0, requires_grad=True)
y = w ** 2 + 3 * w
y.backward()                 # autograd does the chain rule for us
print("y =", y.item(), " dy/dw =", w.grad.item())

y = 10.0  dy/dw = 7.0

A network is a class that inherits from nn.Module: layers are defined in __init__ and the forward pass in forward. Then the training loop repeats four steps: predict, compute the loss, backward() for gradients, and optimizer.step() to update the weights. We use the breast cancer data again, scaled with statistics from the training rows only.

import torch, torch.nn as nn
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler
torch.manual_seed(42); torch.set_num_threads(2)

d = load_breast_cancer()
X_tr, X_te, y_tr, y_te = train_test_split(d.data, d.target, test_size=0.25,
                                          stratify=d.target, random_state=42)
sc = StandardScaler().fit(X_tr)
Xtr = torch.tensor(sc.transform(X_tr), dtype=torch.float32)
Xte = torch.tensor(sc.transform(X_te), dtype=torch.float32)
ytr = torch.tensor(y_tr, dtype=torch.float32).unsqueeze(1)
yte = torch.tensor(y_te, dtype=torch.float32).unsqueeze(1)

class Net(nn.Module):
    def __init__(self, n_in, hidden=16):
        super().__init__()
        self.layers = nn.Sequential(nn.Linear(n_in, hidden), nn.ReLU(), nn.Linear(hidden, 1))
    def forward(self, x):
        return self.layers(x)          # raw score; the loss applies the sigmoid

model = Net(Xtr.shape[1])
print(model)

Net(
  (layers): Sequential(
    (0): Linear(in_features=30, out_features=16, bias=True)
    (1): ReLU()
    (2): Linear(in_features=16, out_features=1, bias=True)
  )
)
loss_fn = nn.BCEWithLogitsLoss()                    # sigmoid + cross-entropy in one
opt = torch.optim.Adam(model.parameters(), lr=0.01)
for epoch in range(1, 61):
    model.train()
    opt.zero_grad()                  # clear old gradients
    loss = loss_fn(model(Xtr), ytr)  # predict + loss
    loss.backward()                  # gradients
    opt.step()                       # update weights
    if epoch in (1, 10, 30, 60):
        print(f"epoch {epoch:2d}  train loss {loss.item():.4f}")

model.eval()
with torch.no_grad():                # no gradients needed for evaluation
    pred = (torch.sigmoid(model(Xte)) > 0.5).float()
print("test accuracy:", round((pred == yte).float().mean().item(), 3))

epoch  1  train loss 0.7296
epoch 10  train loss 0.2742
epoch 30  train loss 0.0784
epoch 60  train loss 0.0465
test accuracy: 0.972

Watch out. Common mistake: forgetting opt.zero_grad(). PyTorch adds new gradients to old ones, so the updates go wrong. Also call model.eval() and torch.no_grad() when predicting.

#14.8 Training well: overfitting, regularisation, optimisers, learning rate

A network with many parameters can overfit: it memorises the training rows and does worse on new ones (see Part 9). The sign is a training loss that keeps falling while the validation loss turns upward. Here we deliberately give a big network only 60 training rows. A small helper trains a model and records both curves.

import numpy as np, torch, torch.nn as nn
from sklearn.model_selection import train_test_split
torch.set_num_threads(2)

# small training set (60 rows) to force overfitting; validation from the rest
Xs, _, ys, _ = train_test_split(Xtr.numpy(), ytr.numpy(), train_size=60,
                                stratify=ytr.numpy().ravel(), random_state=0)
Xs, ys = torch.tensor(Xs), torch.tensor(ys)

def make(drop=0.0):
    return nn.Sequential(nn.Linear(30, 64), nn.ReLU(), nn.Dropout(drop),
                         nn.Linear(64, 64), nn.ReLU(), nn.Dropout(drop), nn.Linear(64, 1))

def fit(model, opt, epochs=150):
    tr_curve, va_curve = [], []
    for _ in range(epochs):
        model.train(); opt.zero_grad()
        loss = loss_fn(model(Xs), ys); loss.backward(); opt.step()
        model.eval()
        with torch.no_grad():
            va_curve.append(loss_fn(model(Xte), yte).item())
        tr_curve.append(loss.item())
    return tr_curve, va_curve

torch.manual_seed(0)
m1 = make(0.0)
plain = fit(m1, torch.optim.Adam(m1.parameters(), lr=0.01))
torch.manual_seed(0)
m2 = make(0.3)
reg = fit(m2, torch.optim.Adam(m2.parameters(), lr=0.01, weight_decay=0.01))
print("plain : train %.4f  validation %.4f" % (plain[0][-1], plain[1][-1]))
print("regularised: train %.4f  validation %.4f" % (reg[0][-1], reg[1][-1]))

plain : train 0.0000  validation 0.3679
regularised: train 0.0114  validation 0.0760
import matplotlib.pyplot as plt
fig, axes = plt.subplots(1, 2, figsize=(10, 3.6), sharey=True)
for ax, (name, (tr, va)) in zip(axes, [("No regularisation", plain),
                                       ("Dropout 0.3 + weight decay", reg)]):
    ax.plot(tr, color=BLUE, lw=2, label="training loss")
    ax.plot(va, color=AMBER, lw=2, label="validation loss")
    ax.set_title(name, color=DARK); ax.set_xlabel("epoch"); ax.legend()
axes[0].set_ylabel("cross-entropy loss")
plt.suptitle("Overfitting curves on 60 training rows", color=DARK)
plt.tight_layout(); plt.savefig("p14_fig2.png", dpi=130); plt.close()
print("saved p14_fig2.png")

saved p14_fig2.png

Training loss keeps falling in both panels; the validation loss is the one to watch.

Three tools fight overfitting. Weight decay (L2, the same idea as ridge in Part 10) penalises large weights. Dropout randomly switches off a share of neurons at every training step so no neuron can be relied on too much; it is active only in model.train() mode. Early stopping watches the validation loss and stops when it has not improved for a few epochs, keeping the best weights.

import copy
torch.manual_seed(0)
model = make(0.0)
opt = torch.optim.Adam(model.parameters(), lr=0.01)
best, best_state, wait, patience = 1e9, None, 0, 10
for epoch in range(1, 301):
    model.train(); opt.zero_grad()
    loss_fn(model(Xs), ys).backward(); opt.step()
    model.eval()
    with torch.no_grad():
        val = loss_fn(model(Xte), yte).item()
    if val < best - 1e-4:
        best, best_state, wait = val, copy.deepcopy(model.state_dict()), 0
    else:
        wait += 1
        if wait >= patience:
            break
model.load_state_dict(best_state)
print(f"stopped at epoch {epoch}, best validation loss {best:.4f}")

stopped at epoch 18, best validation loss 0.1181

In real projects the stopping signal should come from a separate validation set, with the test set kept for one final check. Here we reuse the test rows to keep the example short.

The optimiser decides how to use the gradients. SGD (stochastic gradient descent) takes plain downhill steps, often with momentum to keep rolling. Adam adapts the step for every weight and is the safe default. The learning rate matters most: compare the same network with different rates.

def final_loss(opt_name, lr, epochs=100):
    torch.manual_seed(0)
    m = make(0.0)
    if opt_name == "SGD":
        opt = torch.optim.SGD(m.parameters(), lr=lr, momentum=0.9)
    else:
        opt = torch.optim.Adam(m.parameters(), lr=lr)
    return fit(m, opt, epochs)[0][-1]

rows = []
for name, lr in [("SGD", 0.001), ("SGD", 0.01), ("Adam", 0.0001), ("Adam", 0.01), ("Adam", 0.5)]:
    rows.append((name, lr, round(final_loss(name, lr), 4)))
import pandas as pd
pd.DataFrame(rows, columns=["optimiser", "learning rate", "final train loss"])
optimiser learning rate final train loss
0 SGD 0.0010 0.6045
1 SGD 0.0100 0.0273
2 Adam 0.0001 0.5413
3 Adam 0.0100 0.0000
4 Adam 0.5000 0.0001

Very small rates are still far from the best loss after the same number of epochs; a large rate can fit the training rows quickly but may bounce or overfit, so judge by validation loss. Start with Adam at 0.001 to 0.01, and change one thing at a time.

Practice question. Practice: why is dropout turned off by model.eval()? Answer: at prediction time we want the full, stable network with all neurons; random switching is only a training trick to stop co-dependence.

#14.9 Convolutional neural networks for images

An image is a grid of numbers, and neighbouring pixels belong together. A convolutional neural network (CNN) uses this. A small grid of weights called a kernel (or filter) slides over the image; at each position it multiplies and adds up the pixels under it. Different kernels detect different patterns, such as edges. First do it by hand on a 6x6 image with a dark left half and a bright right half.

import numpy as np
img = np.zeros((6, 6)); img[:, 3:] = 1.0          # left dark, right bright
kernel = np.array([[-1, 0, 1],
                   [-1, 0, 1],
                   [-1, 0, 1]], dtype=float)        # responds to dark-to-bright vertical edges

def convolve(im, k):
    n = im.shape[0] - k.shape[0] + 1
    out = np.zeros((n, n))
    for i in range(n):
        for j in range(n):
            out[i, j] = np.sum(im[i:i+3, j:j+3] * k)
    return out

print(convolve(img, kernel))

[[0. 3. 3. 0.]
 [0. 3. 3. 0.]
 [0. 3. 3. 0.]
 [0. 3. 3. 0.]]

The output is large only in the columns where the image changes from dark to bright: the kernel found the vertical edge. A CNN learns its kernels instead of us choosing them, and stacks many. Pooling (for example max pooling) shrinks the map by keeping the strongest value in each small block, so the network cares about what is present more than exactly where. Now a real task: scikit-learn's load_digits, 1,797 handwritten digits as 8x8 images.

import numpy as np, torch, torch.nn as nn
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split
torch.manual_seed(42); torch.set_num_threads(2)

dg = load_digits()
Xd = torch.tensor(dg.images / 16.0, dtype=torch.float32).unsqueeze(1)   # (N, 1 channel, 8, 8)
yd = torch.tensor(dg.target)
idx_tr, idx_te = train_test_split(np.arange(len(yd)), test_size=0.25, stratify=dg.target,
                                  random_state=42)
Xd_tr, Xd_te, yd_tr, yd_te = Xd[idx_tr], Xd[idx_te], yd[idx_tr], yd[idx_te]
print("image batch shape (N, channels, H, W):", tuple(Xd_tr.shape))

cnn = nn.Sequential(
    nn.Conv2d(1, 8, kernel_size=3, padding=1), nn.ReLU(),   # 8 learned 3x3 filters
    nn.MaxPool2d(2),                                        # 8x8 -> 4x4
    nn.Flatten(), nn.Linear(8 * 4 * 4, 10))                 # 10 digit classes
print("parameters:", sum(p.numel() for p in cnn.parameters()))

ce = nn.CrossEntropyLoss()                                  # for many classes
for epoch in range(1, 16):
    cnn.train()
    perm = torch.randperm(len(Xd_tr))

#14.10 Recurrent networks and LSTMs for sequences

Some data is an ordered sequence: daily M-Pesa balances, sensor readings, words in a sentence. A recurrent neural network (RNN) reads one step at a time and carries a hidden state, a short memory, forward. Plain RNNs forget quickly. An LSTM (long short-term memory) adds gates that decide what to keep and what to drop, so it remembers longer. Tiny task (synthetic): each sequence is 10 days of net cash flow for a small shop; the label is 1 if the total for the 10 days is positive. The network must remember information across days.

import numpy as np, torch, torch.nn as nn
torch.manual_seed(42); torch.set_num_threads(2)
rng = np.random.default_rng(42)

seqs = rng.normal(size=(1200, 10, 1)).astype("float32")   # (samples, days, 1 feature)
labels = (seqs.sum(axis=(1, 2)) > 0).astype("float32")
Xs_tr, Xs_te = torch.tensor(seqs[:900]), torch.tensor(seqs[900:])
ys_tr = torch.tensor(labels[:900]).unsqueeze(1)
ys_te = torch.tensor(labels[900:]).unsqueeze(1)
print("sequence batch shape (samples, time steps, features):", tuple(Xs_tr.shape))

class SeqNet(nn.Module):
    def __init__(self):
        super().__init__()
        self.lstm = nn.LSTM(input_size=1, hidden_size=16, batch_first=True)
        self.head = nn.Linear(16, 1)
    def forward(self, x):
        out, (h, c) = self.lstm(x)        # h: memory after the last day
        return self.head(h[-1])

net = SeqNet()
opt = torch.optim.Adam(net.parameters(), lr=0.02)
bce = nn.BCEWithLogitsLoss()
for epoch in range(1, 31):
    net.train(); opt.zero_grad()
    bce(net(Xs_tr), ys_tr).backward(); opt.step()
net.eval()
with torch.no_grad():
    acc = ((net(Xs_te) > 0).float() == ys_te).float().mean().item()
print("test accuracy:", round(acc, 3))

sequence batch shape (samples, time steps, features): (900, 10, 1)
test accuracy: 0.933

Shapes matter: PyTorch wants (samples, time steps, features) when batch_first=True. LSTMs were the standard for text and time series for years; today transformers (section 14.12) replaced them for language, but LSTMs and the simpler GRU are still handy for small sensor and forecasting jobs. For plain forecasting, try the classical methods of Part 10 first.

#14.11 Autoencoders: compression and anomaly detection

An autoencoder is a network trained to copy its input to its output through a narrow middle, the bottleneck. To succeed it must squeeze the data into a short code (compression) and rebuild it. If it only ever sees normal data, it rebuilds normal rows well and unusual rows badly. A large reconstruction error is therefore an anomaly score, useful when you have few or no labelled frauds. Here we train on benign tumours only and see whether malignant ones stand out (the same pattern fits card transactions or machine sensors).

import numpy as np, torch, torch.nn as nn
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler
from sklearn.metrics import roc_auc_score
torch.manual_seed(42); torch.set_num_threads(2)

d = load_breast_cancer()
X_a, X_b, y_a, y_b = train_test_split(d.data, d.target, test_size=0.3, stratify=d.target,
                                      random_state=42)
sc = StandardScaler().fit(X_a[y_a == 1])                 # label 1 = benign ("normal")
Xn = torch.tensor(sc.transform(X_a[y_a == 1]), dtype=torch.float32)
Xt = torch.tensor(sc.transform(X_b), dtype=torch.float32)

ae = nn.Sequential(nn.Linear(30, 12), nn.ReLU(), nn.Linear(12, 4),      # encoder: 30 -> 4
                   nn.ReLU(), nn.Linear(4, 12), nn.ReLU(), nn.Linear(12, 30))  # decoder: 4 -> 30
opt = torch.optim.Adam(ae.parameters(), lr=0.01)
for epoch in range(200):
    opt.zero_grad()
    loss = nn.functional.mse_loss(ae(Xn), Xn); loss.backward(); opt.step()
print("compression: 30 numbers -> 4 numbers; final reconstruction loss", round(loss.item(), 4))

ae.eval()
with torch.no_grad():
    err = ((ae(Xt) - Xt) ** 2).mean(1).numpy()           # reconstruction error per row
is_malignant = (y_b == 0)
print("mean error, benign   :", err[~is_malignant].mean().round(3))
print("mean error, malignant:", err[is_malignant].mean().round(3))
print("AUC of error as an anomaly score:", round(roc_auc_score(is_malignant, err), 3))

compression: 30 numbers -> 4 numbers; final reconstruction loss 0.1818
mean error, benign   : 0.247
mean error, malignant: 2.953
AUC of error as an anomaly score: 0.948
import matplotlib.pyplot as plt
fig, ax = plt.subplots(figsize=(10, 3.6))
bins = np.linspace(0, np.percentile(err, 98), 30)
ax.hist(err[~is_malignant], bins=bins, color=BLUE, alpha=0.8, label="benign (normal)")
ax.hist(err[is_malignant], bins=bins, color=AMBER, alpha=0.8, label="malignant (anomaly)")
ax.set_title("Reconstruction error of the autoencoder on held-out rows", color=DARK)
ax.set_xlabel("mean squared reconstruction error per row"); ax.set_ylabel("number of rows")
ax.legend(); plt.tight_layout(); plt.savefig("p14_fig4.png", dpi=130); plt.close()

Malignant rows (amber) sit further right: the autoencoder rebuilds them badly because it only learned what normal looks like.

Autoencoders also compress: the 4-number code can feed a clustering or plotting step, like PCA in Part 13 but able to learn curved structure. Choose the alert threshold from the business cost: a lower threshold catches more but raises more false alarms.

Using it in the real world. Using it in the real world. Data: thousands of labelled or unlabelled examples; clean, scaled inputs; for images or sequences, a consistent format. Validate on rows from a LATER period than training (for a SACCO or lender, train on last year and test on this quarter), and compare with a simple baseline such as logistic regression or a gradient-boosted model (Part 12). How it fails: it memorises small data, breaks when customers or devices change (drift), and gives confident wrong answers on inputs unlike its training data. Monitor input distributions, the share of high anomaly scores, and accuracy once true outcomes arrive; retrain on a schedule and keep humans reviewing high-stakes decisions such as loan refusals.

#Transfer learning and pretrained models

Training a large network needs huge data and compute. Transfer learning starts from a network already trained on millions of images (or documents), freezes most of it and retrains only a small last layer on your own examples. A few hundred photos of maize leaf disease can be enough. This code needs a download (no internet in this build), so it is shown but not run.

import torch.nn as nn
from torchvision import models

net = models.resnet18(weights=models.ResNet18_Weights.DEFAULT)   # pretrained on ImageNet
for p in net.parameters():
    p.requires_grad = False                    # freeze the learned image features
net.fc = nn.Linear(net.fc.in_features, 3)      # new last layer: e.g. healthy / rust / blight
# then train only net.fc with the usual loop on your own labelled leaf photos

#A preview of transformers

The transformer is the architecture behind modern language models. Instead of reading one word at a time like an LSTM, it uses attention: every word looks at every other word in the sentence and decides which ones matter for its meaning, and all words are handled in parallel. That makes it trainable on very large text collections. Part 16 builds on this to explain large language models and generative AI.

#When deep learning wins and when it does not

Deep learning shines on unstructured data (images, audio, text, sequences) and on huge datasets. On ordinary tables (customers, loans, transactions), gradient-boosted trees (Part 12) are usually as good or better, train faster, need less data and are easier to explain, which matters for credit decisions. Always beat a simple baseline first.

Task Good first choice Why
Small or medium table, yes/no or number Logistic / linear model, random forest, XGBoost Fast, strong, explainable
Large table with complex interactions Gradient boosting; MLP as a challenger Boosting rarely loses on tables
Photos, scans, handwriting CNN; transfer learning if data is small Learns visual patterns
Ordered signals (sensors, balances) Classical time series first; LSTM or GRU if complex Check simple methods first
Text and language Pretrained transformer (Part 16) Far better than training your own
Anomalies, few fraud labels Isolation forest (Part 13) or autoencoder No labels needed
Compression, visualisation PCA first, autoencoder for curved structure PCA is simpler and exact

Using it in the real world. Using it in the real world. Start with a simple model as the benchmark and use a network only if it clearly wins on a held-out, later-in-time test set. Document the data, the seed, the metric and the threshold. Check results for fairness across groups (for example counties or gender) before any decision about people. After deployment, monitor drift and retrain; see Part 18.

Key takeaways
  • A neuron is a weighted sum plus bias passed through an activation; layers of neurons make a network.
  • Training = forward pass, loss, backpropagation (gradients), then a small step downhill.
  • Scale your features; use MLPClassifier for a quick start and PyTorch when you need control.
  • Watch the validation loss: dropout, weight decay and early stopping fight overfitting.
  • CNNs suit images, LSTMs suit sequences, autoencoders suit compression and anomalies.
  • On ordinary tables, beat a boosted-tree baseline before choosing deep learning.
