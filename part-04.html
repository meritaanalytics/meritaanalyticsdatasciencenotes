Pandas: Working with Tables

Pandas is the Python library for tables. You will go from a single column to cleaning a messy file, grouping, merging and reshaping, then finish with validation, speed tips and real World Bank data. Each step builds only on the ones before it.

In this part
  • Build and read a Series and a DataFrame, and load or save CSV, Excel and database data
  • Take a first look at any table: shape, types, summary numbers and missing values
  • Select, filter, sort and create columns without changing the original by accident
  • Clean missing values, duplicates, text and dates
  • Group, merge, reshape and run window calculations, then check your own work

#4.1 Series and DataFrame

Pandas is the Python library for tables. A Series is one labelled column of values. A DataFrame is a table made of Series that share one index (the row labels). Analysts use pandas because one tool handles mixed types, missing values, dates, joins and grouping, which in a spreadsheet or in SQL you would do in separate places.

import numpy as np

print(units)

print((units * 2).to_dict())

Selecting one column gives a Series; selecting a list of columns gives a DataFrame. This difference (single versus double square brackets) matters later.

Rule. Pandas lines values up by index label, not by position. Adding two Series with different labels gives missing values (NaN) where labels do not match.

a = pd.Series([1, 2, 3], index=["x", "y", "z"])
b = pd.Series([10, 20, 30], index=["y", "z", "w"])
print(a + b)

Common mistake. Worrying that changing a selected column also changes the original. In pandas 3.0 Copy-on-Write is always on: every derived object behaves like an independent copy, so changing a slice never alters its parent.

#Dates

Dates read from a file are text until you convert them. pd.to_datetime with an explicit format is safest, because 03/04/2026 could mean 3 April or 4 March. With errors="coerce", impossible dates such as 30 February become NaT (the date version of NaN).

raw = pd.Series(["2026-01-05", "2026-02-30", "2026-03-14", "bad"])
dates = pd.to_datetime(raw, format="%Y-%m-%d", errors="coerce")
print(dates.tolist())
print("unparseable:", int(dates.isna().sum()))

[Timestamp('2026-01-05 00:00:00'), NaT, Timestamp('2026-03-14 00:00:00'), NaT]
unparseable: 2

#4.6 Grouping and aggregation

Grouping splits a table into pieces (one per county, one per month), computes a summary for each piece, and puts the results back in a table. It is the pandas version of a SQL GROUP BY or an Excel pivot table. The next sections use a synthetic sales table with 400 rows, generated with a fixed seed.

import numpy as np
import pandas as pd

rng = np.random.default_rng(7)
n = 400
sales = pd.DataFrame({
    "date": pd.Timestamp("2026-01-01") + pd.to_timedelta(rng.integers(0, 120, n), unit="D"),
    "county": rng.choice(["Nairobi", "Mombasa", "Kisumu", "Nakuru"], n, p=[.4, .25, .2, .15]),
    "product": rng.choice(["Charger", "Remote", "HDMI cable", "TV stand"], n, p=[.4, .3, .2, .1]),
    "units": rng.integers(1, 12, n),
})
price = {"Charger": 250, "Remote": 150, "HDMI cable": 300, "TV stand": 3400}

#transform and filter

agg returns one row per group. transform returns one value per original row, so you can put a group total beside each row and compute shares. filter keeps or drops whole groups.

sales["county_total"] = sales.groupby("county")["revenue_ksh"].transform("sum")
sales["share_of_county_pct"] = sales["revenue_ksh"] / sales["county_total"] * 100
print(sales.groupby("county")["share_of_county_pct"].sum().round(1).to_dict())   # each county = 100
busy = sales.groupby("product").filter(lambda g: len(g) > 100)
print(sorted(busy["product"].unique()))

{'Kisumu': 100.0, 'Mombasa': 100.0, 'Nairobi': 100.0, 'Nakuru': 100.0}
['Charger', 'Remote']

Common mistake. Missing values in the group key are dropped by default. Use groupby(..., dropna=False) if rows with a missing county must appear as their own group.

#4.7 Combining tables safely

A merge (join) attaches columns from one table to another using a shared key, like a VLOOKUP or a SQL JOIN. The risk is silent: a wrong key can duplicate rows or lose them without any error. Always check row counts before and after.

customers = pd.DataFrame({"customer_id": ["C1", "C2", "C3", "C4"],
                          "county": ["Nairobi", "Kisumu", "Nakuru", "Mombasa"]})
loans = pd.DataFrame({"loan_id": ["L1", "L2", "L3", "L4", "L5"],
                      "customer_id": ["C1", "C1", "C2", "C3", "C9"],
                      "principal_ksh": [10000, 5000, 20000, 8000, 4000]})
inner = loans.merge(customers, on="customer_id", how="inner")
left = loans.merge(customers, on="customer_id", how="left", indicator=True)
print(len(loans), "loans | inner:", len(inner), "| left:", len(left))
left[["loan_id", "customer_id", "county", "_merge"]]

5 loans | inner: 4 | left: 5
loan_id customer_id county _merge
0 L1 C1 Nairobi both
1 L2 C1 Nairobi both
2 L3 C2 Kisumu both
3 L4 C3 Nakuru both
4 L5 C9 NaN left_only

An inner merge keeps only matches, so loan L5 (customer C9 does not exist) vanished. A left merge keeps every loan, and indicator=True adds a _merge column that says which rows found no partner. Use it to count orphans: (left['_merge'] == 'left_only').sum().

#The merge inflation trap

If the key is not unique on the side you expected to be unique, each match multiplies rows and your totals inflate. validate= makes pandas stop with an error instead.

cust_dup = pd.concat([customers, customers.iloc[[0]]], ignore_index=True)   # C1 twice by mistake
bad = loans.merge(cust_dup, on="customer_id", how="left")
print("loans:", len(loans), "| after merge:", len(bad))
print("principal before:", loans["principal_ksh"].sum(), "| after:", bad["principal_ksh"].sum())

loans: 5 | after merge: 7
principal before: 47000 | after: 62000
loans.merge(cust_dup, on="customer_id", how="left", validate="many_to_one")
Error on purposeMergeError: Merge keys are not unique in right dataset; not a many-to-one merge
validate= Meaning Typical use
one_to_one keys unique on both sides two tables about the same entities
many_to_one unique on the right only facts joined to a lookup table
one_to_many unique on the left only a customer joined to many loans

#Other joins and stacking

When key names differ use left_on and right_on; when both tables share another column name, suffixes labels them. To stack tables with the same columns (for example monthly files) use pd.concat.

m = sales.head(5).merge(prices, left_on="product", right_on="sku", how="left")
print(m[["product", "sku", "price_ksh"]].to_string(index=False))
jan = pd.DataFrame({"month": "Jan", "sales": [10, 20]})
feb = pd.DataFrame({"month": "Feb", "sales": [30, 40]})
print(pd.concat([jan, feb], ignore_index=True).shape)

#4.8 Reshaping: pivot, melt and crosstab

Long format has one row per observation (county, month, value), which is what grouping and plots prefer. Wide format has one column per category, which is what people like to read. pivot_table goes long to wide; melt goes back.

sales["month"] = sales["date"].dt.strftime("%Y-%m")
wide = sales.pivot_table(index="county", columns="month", values="revenue_ksh",
                         aggfunc="sum", fill_value=0, margins=True, margins_name="Total")

#Memory and speed

Three habits keep pandas fast. (1) Store repeated labels as category and numbers in the smallest safe type. (2) Vectorise: operate on whole columns instead of looping or using apply row by row. (3) Load only the columns you need (usecols).

import time
r = np.random.default_rng(1)
big = pd.DataFrame({"county": r.choice(["Nairobi", "Kisumu", "Nakuru"], 200_000),
                    "qty": r.integers(1, 50, 200_000)})
before = big.memory_usage(deep=True).sum()
big["county"] = big["county"].astype("category")
big["qty"] = pd.to_numeric(big["qty"], downcast="unsigned")
print("memory smaller:", big.memory_usage(deep=True).sum() < before, "| qty dtype:", big["qty"].dtype)

t = time.perf_counter(); slow = big["qty"].apply(lambda q: q * 2 + 1); t_slow = time.perf_counter() - t
t = time.perf_counter(); fast = big["qty"].astype("int64") * 2 + 1; t_fast = time.perf_counter() - t
print("same result:", (slow.astype("int64") == fast).all(), "| vectorised faster:", t_fast < t_slow)

#Method chaining and a reusable pipeline

Wrap your cleaning into small functions and chain them with .pipe. The steps then read top to bottom, can be tested one by one, and are easy to re-run when next month's file arrives (Part 18 automates this).

def tidy_names(d):
    return d.rename(columns=lambda c: c.strip().lower().replace(" ", "_"))

def tidy_text(d):
    return d.assign(county=d["county"].str.strip().str.title())

def add_value(d):
    return d.assign(value_ksh=d["price_per_unit"] * d["quantity"])

out = (raw.pipe(tidy_names).drop_duplicates().pipe(tidy_text)
       .assign(price_per_unit=lambda d: pd.to_numeric(d["price_per_unit"].astype("string")
               .str.replace(r"[^0-9.]", "", regex=True), errors="coerce"))
       .query("quantity > 0").pipe(add_value))
print("shape:", out.shape, "| rows with a value:", int(out["value_ksh"].notna().sum()))

shape: (280, 9) | rows with a value: 265

Safe editing. Never write df[df.a > 1]["b"] = 0. Under Copy-on-Write that changes a temporary copy and the original stays the same. Use one loc: df.loc[df["a"] > 1, "b"] = 0.

Key takeaways
  • A Series is one labelled column and a DataFrame is a table; pandas lines data up by index label.
  • Take the same first look at every table: shape, info, describe, value_counts and isna().sum().
  • Filter with brackets, &, |, isin and query; use loc for labels and iloc for positions.
  • Clean one problem at a time on a copy, keep rejected rows, and log the row count after every step.
  • Merge with validate= and indicator=True, and compare row counts and one total before and after.
  • Put groupby before shift, pct_change and rolling, and write your assumptions as checks.
