Part 10

Regression

Predict a number: from a straight line to forests and boosting, with the metrics and checks that tell you if the prediction can be trusted.

In this part
  • Fit and read a linear regression, simple and multiple.
  • Measure a regression with MAE, RMSE, R2 and MAPE, and check the residuals.
  • Use polynomial features and ridge, lasso and elastic net to control flexibility.
  • Use KNN, trees, random forests, gradient boosting and SVR, and know when each fits.
  • Compare all of them fairly and pick one with the algorithm chooser.
You need first Part 9Time 5 to 7 hours

#10.1 What is regression, and how do we score it?

Regression predicts a number: a price, a demand, an amount of money. The model's guess is the prediction; the gap between truth and guess is the error or residual (residual = actual - predicted). Four scores are used everywhere.

Metric Meaning Units Good to know
MAE mean absolute error average size of the miss same as target easy to explain to a manager
RMSE root mean squared error like MAE but big misses count more same as target punishes large errors
R2 (R-squared) share of variation explained; 1 is perfect, 0 is no better than the average none can be negative on new data
MAPE mean absolute percentage error average miss as a percent of the truth percent breaks when a true value is 0 
import numpy as np
from sklearn.metrics import mean_absolute_error, mean_squared_error, r2_score, mean_absolute_percentage_error
actual = np.array([200.0, 250.0, 300.0, 400.0])      # synthetic: weekly sales, Ksh thousands
pred = np.array([210.0, 240.0, 330.0, 380.0])
print("MAE :", mean_absolute_error(actual, pred))
print("RMSE:", round(mean_squared_error(actual, pred) ** 0.5, 2))
print("R2  :", round(r2_score(actual, pred), 3))
print("MAPE:", round(100 * mean_absolute_percentage_error(actual, pred), 1), "%")

MAE : 17.5
RMSE: 19.36
R2  : 0.931
MAPE: 6.0 %

Tip. Report MAE or RMSE in the target's own units (Ksh) and compare against a dummy baseline (Part 9). An R2 on its own hides whether the error is small enough to be useful.

#Our two datasets

Diabetes is scikit-learn's built-in dataset (BSD licence): 442 patients, ten body measurements, and a score of disease progression after one year. Electricity demand is a clearly labelled synthetic table we generate: daily demand in megawatts depends on temperature (cooling and heating both raise it), the weekend, and factory activity. It is made nonlinear on purpose, so you can see where straight lines struggle.

import numpy as np, pandas as pd
from sklearn.datasets import load_diabetes
Xd, yd = load_diabetes(return_X_y=True, as_frame=True)

rng = np.random.default_rng(42)
n = 600
power = pd.DataFrame({"temp_c": rng.uniform(12, 34, n),
                      "weekend": rng.integers(0, 2, n),
                      "factory_index": rng.uniform(60, 120, n)})
power["demand_mw"] = (300 + 1.8 * (power["temp_c"] - 22) ** 2 - 40 * power["weekend"]
                      + 2.0 * power["factory_index"] + rng.normal(0, 15, n))
Xp, yp = power.drop(columns="demand_mw"), power["demand_mw"]
print("diabetes:", Xd.shape, "| synthetic demand:", Xp.shape)
power.describe().loc[["mean", "min", "max"]].round(1)

temp_c weekend factory_index demand_mw

#10.2 Simple linear regression

What it does: draws the best straight line through the points: y = w*x + b. How it works: it picks the slope w and intercept b that make the sum of squared residuals smallest (the least-squares rule; Part 9 found the same line by gradient descent). Works best when the link between x and y is roughly straight. Struggles when the link curves or outliers pull the line. Key settings: none, it has no hyperparameters.

from sklearn.linear_model import LinearRegression
from sklearn.model_selection import train_test_split
from sklearn.metrics import mean_absolute_error, r2_score
Xtr, Xte, ytr, yte = train_test_split(Xd, yd, test_size=0.2, random_state=42)
lin1 = LinearRegression().fit(Xtr[["bmi"]], ytr)
p = lin1.predict(Xte[["bmi"]])
print("slope for bmi:", round(lin1.coef_[0], 1), "| intercept:", round(lin1.intercept_, 1))
print("test MAE:", round(mean_absolute_error(yte, p), 1), "| test R2:", round(r2_score(yte, p), 3))

slope for bmi: 998.6 | intercept: 152.0
test MAE: 52.3 | test R2: 0.233

import seaborn as sns
sns.set_theme(style="whitegrid")
BLUE, GREEN, GREY, DARK, AMBER = "#1F5FD6", "#2BB38A", "#9CA3AF", "#0B2A4A", "#B45309"
fig, ax = plt.subplots(figsize=(10, 3.6))
ax.scatter(Xte["bmi"], yte, color=GREY, s=20, label="test patients")

#10.3 Multiple linear regression and its coefficients

Multiple regression uses many features: y = w1x1 + w2x2 + ... + b. Each coefficient says how much the prediction changes when that feature rises by one unit while the others stay fixed. This makes linear models easy to explain, which matters in lending and health.

lin = LinearRegression().fit(Xtr, ytr)
coefs = pd.Series(lin.coef_, index=Xtr.columns).round(0).sort_values()
print(coefs.to_string())
print("test R2, all features:", round(r2_score(yte, lin.predict(Xte)), 3))

Common mistake. Coefficients of strongly related features (here s1 and s2) can be large and opposite; do not read one of them alone. Ridge (10.6) steadies them.

#10.4 Residual checks

Before trusting a regression, plot its residuals against the predictions. A good model leaves a shapeless cloud around zero. A curve or a funnel means the model is missing a pattern or the error grows with size.

res = yte - lin.predict(Xte)
fig, ax = plt.subplots(1, 2, figsize=(10, 3.6))
ax[0].scatter(lin.predict(Xte), res, color=BLUE, s=18)
ax[0].axhline(0, color=AMBER)
ax[0].set_xlabel("Predicted progression"); ax[0].set_ylabel("Residual (actual - predicted)")
ax[0].set_title("Residuals vs predictions", color=DARK)
ax[1].hist(res, bins=20, color=GREEN)
ax[1].set_xlabel("Residual"); ax[1].set_ylabel("Number of patients")
ax[1].set_title("Residuals are roughly bell-shaped", color=DARK)
plt.tight_layout(); plt.savefig("p10_fig2.png", dpi=130); plt.close(); print("saved p10_fig2.png")

saved p10_fig2.png

The residuals centre on zero with no strong curve, so a straight-line model is a fair start for this data. Look for any very large residuals: they are cases the model gets badly wrong.

#10.5 Polynomial features

What it does: lets a linear model draw curves by adding squared (and higher) copies of a feature. How it works: from x it makes x, x squared, x cubed, and fits a normal linear regression on all of them, so the model is still linear in its weights. Works best when the curve is smooth. Struggles when the degree is high (overfitting, Part 9). Key setting: degree.

On the synthetic demand data, demand bends with temperature, so a straight line misses it.

from sklearn.preprocessing import PolynomialFeatures
from sklearn.pipeline import make_pipeline
Xptr, Xpte, yptr, ypte = train_test_split(Xp, yp, test_size=0.25, random_state=42)
for deg in (1, 2):
    m = make_pipeline(PolynomialFeatures(deg), LinearRegression()).fit(Xptr[["temp_c"]], yptr)
    q = m.predict(Xpte[["temp_c"]])
    print(f"degree {deg}: test MAE {mean_absolute_error(ypte, q):6.1f} MW | R2 {r2_score(ypte, q):.3f}")

degree 1: test MAE   63.0 MW | R2 -0.000
degree 2: test MAE   35.3 MW | R2 0.676

Degree 2 captures the bend. Choose the degree by cross-validation, not by the training score.

#10.6 Ridge, lasso and elastic net (regularisation)

When a model has many features or related features, the weights can grow wild and the model overfits. Regularisation adds a penalty on large weights so the model stays simpler. Ridge penalises the sum of squared weights: it shrinks them all, keeping every feature. Lasso penalises the sum of absolute weights: it can shrink some weights to exactly zero, so it also does feature selection. Elastic net mixes both. The key setting is alpha, the penalty strength (bigger is simpler); elastic net also has l1_ratio, the lasso share. Scale features first, because the penalty treats all weights equally.

from sklearn.linear_model import Ridge, Lasso, ElasticNet
from sklearn.preprocessing import StandardScaler
models = {"linear": LinearRegression(), "ridge": Ridge(alpha=10),
          "lasso": Lasso(alpha=2), "elastic net": ElasticNet(alpha=1, l1_ratio=0.5)}
for name, mdl in models.items():
    pipe = make_pipeline(StandardScaler(), mdl).fit(Xtr, ytr)
    zeros = int((np.abs(pipe[-1].coef_) < 1e-9).sum())
    print(f"{name:12s} test R2 {r2_score(yte, pipe.predict(Xte)):.3f} | weights set to zero: {zeros}")

linear       test R2 0.453 | weights set to zero: 0
ridge        test R2 0.457 | weights set to zero: 0
lasso        test R2 0.472 | weights set to zero: 3
elastic net  test R2 0.455 | weights set to zero: 0

Lasso drops the features it finds least useful. Use RidgeCV, LassoCV or ElasticNetCV to choose alpha automatically by cross-validation.

from sklearn.linear_model import LassoCV
lcv = make_pipeline(StandardScaler(), LassoCV(cv=5, random_state=42)).fit(Xtr, ytr)
kept = Xtr.columns[np.abs(lcv[-1].coef_) > 1e-9].tolist()
print("alpha chosen by cross-validation:", round(lcv[-1].alpha_, 3))
print("features kept:", kept)

alpha chosen by cross-validation: 1.655
features kept: ['sex', 'bmi', 'bp', 's1', 's3', 's5', 's6']

Tip. Linear models, regularised or not, are the first thing to try: fast, explainable, and a strong baseline for the harder models.

#10.7 K-nearest neighbours (KNN) regressor

What it does: predicts by looking at similar past cases. How it works: for a new row it finds the k nearest training rows (by distance across the features) and averages their targets. Works best when similar inputs have similar outputs and the data is small and scaled. Struggles when there are many features, unscaled features, or a huge dataset (every prediction searches all rows). Key settings: n_neighbors (small k is jumpy, large k is smooth), weights.

from sklearn.neighbors import KNeighborsRegressor
for k in (1, 5, 15, 40):
    knn = make_pipeline(StandardScaler(), KNeighborsRegressor(n_neighbors=k)).fit(Xtr, ytr)
    print(f"k={k:2d}  train R2 {knn.score(Xtr, ytr):.3f} | test R2 {knn.score(Xte, yte):.3f}")

k= 1  train R2 1.000 | test R2 0.068
k= 5  train R2 0.580 | test R2 0.425
k=15  train R2 0.501 | test R2 0.424
k=40  train R2 0.457 | test R2 0.423

With k=1 the model memorises (training R2 is perfect and test is poor). Larger k values are steadier on the test data.

#10.8 Decision tree regressor

What it does: predicts with a flowchart of yes/no questions. How it works: it repeatedly picks the feature and cut-off (for example temp_c < 25) that splits the rows into two groups with the most similar targets, then predicts the average of each final group (a leaf). Works best when relationships are nonlinear or have thresholds, and when you need to explain the rules. Struggles when it grows deep and overfits, and it changes a lot with small changes in data. Key settings: max_depth, min_samples_leaf.

from sklearn.tree import DecisionTreeRegressor, export_text
tree = DecisionTreeRegressor(max_depth=2, random_state=42).fit(Xptr, yptr)
print(export_text(tree, feature_names=list(Xptr.columns)))
for d in (2, 5, None):
    t = DecisionTreeRegressor(max_depth=d, random_state=42).fit(Xptr, yptr)
    print(f"max_depth={d}: train R2 {t.score(Xptr, yptr):.3f} | test R2 {t.score(Xpte, ypte):.3f}")

A shallow tree is a readable set of rules. An unlimited tree fits the training data perfectly, yet its test score falls below its training score; the forest in the next section fixes this.

#10.9 Random forest regressor

What it does: averages many different trees to get a steadier prediction. How it works: it trains each tree on a random resample of the rows and lets each split see only a random subset of features, so the trees disagree in useful ways; the average cancels much of their individual noise (this is called bagging). Works best when you want a strong, low-effort model for tabular data with mixed features. Struggles when you need a tiny model, instant predictions, or extrapolation beyond the training range. Key settings: n_estimators, max_depth, min_samples_leaf, max_features.

from sklearn.ensemble import RandomForestRegressor
rf = RandomForestRegressor(n_estimators=200, min_samples_leaf=3, random_state=42, n_jobs=2).fit(Xptr, yptr)
tree = DecisionTreeRegressor(random_state=42).fit(Xptr, yptr)
print("single tree test R2  :", round(tree.score(Xpte, ypte), 3))
print("random forest test R2:", round(rf.score(Xpte, ypte), 3))
print(pd.Series(rf.feature_importances_, index=Xptr.columns).round(2).sort_values(ascending=False).to_string())

single tree test R2  : 0.854
random forest test R2: 0.924
temp_c           0.74
factory_index    0.22
weekend          0.04

Feature importance shows which inputs the forest relied on. Treat it as a hint, not proof of cause.

#10.10 Gradient boosting regressor

What it does: builds a strong model from many small trees added one after another. How it works: the first tree makes a rough prediction; the next tree is trained on the remaining errors (the residuals) and its small correction is added; repeat. Each step is scaled by the learning_rate. Works best when you want top accuracy on tabular data. Struggles when the data is very noisy (it can chase noise), and it needs more tuning than a forest. Key settings: n_estimators, learning_rate (smaller needs more trees), max_depth (keep shallow, 2 to 4), subsample.

from sklearn.ensemble import GradientBoostingRegressor
gb = GradientBoostingRegressor(n_estimators=200, learning_rate=0.05, max_depth=3, random_state=42)
gb.fit(Xptr, yptr)
print("gradient boosting test R2:", round(gb.score(Xpte, ypte), 3))
stage = list(gb.staged_predict(Xpte))
for n_trees in (1, 10, 50, 200):
    print(f"after {n_trees:3d} trees: test MAE {mean_absolute_error(ypte, stage[n_trees - 1]):6.1f} MW")

gradient boosting test R2: 0.944
after   1 trees: test MAE   60.0 MW
after  10 trees: test MAE   45.9 MW
after  50 trees: test MAE   21.3 MW
after 200 trees: test MAE   14.9 MW

The error falls as more small corrections are added. The libraries xgboost and lightgbm are faster, more tunable versions of the same idea; they are covered in Part 12.

#10.11 Comparing everything fairly

A fair comparison uses the same data, the same cross-validation folds, and the same metric. We scale inside a pipeline for the models that need it, and report the mean cross-validated RMSE (lower is better) and R2 (higher is better) on both datasets, with the dummy baseline first.

from sklearn.dummy import DummyRegressor
from sklearn.svm import SVR
from sklearn.model_selection import cross_validate, KFold
sc = lambda m: make_pipeline(StandardScaler(), m)
zoo = {"baseline (mean)": DummyRegressor(),
       "linear": sc(LinearRegression()),
       "ridge": sc(Ridge(alpha=10)),
       "lasso": sc(Lasso(alpha=1)),
       "elastic net": sc(ElasticNet(alpha=0.1, l1_ratio=0.5)),
       "poly2 + ridge": sc(make_pipeline(PolynomialFeatures(2), Ridge(alpha=10))),
       "KNN (k=10)": sc(KNeighborsRegressor(n_neighbors=10)),
       "tree (depth 4)": DecisionTreeRegressor(max_depth=4, random_state=42),
       "random forest": RandomForestRegressor(n_estimators=100, min_samples_leaf=3, random_state=42, n_jobs=2),
       "grad boosting": GradientBoostingRegressor(n_estimators=150, learning_rate=0.05, max_depth=3, random_state=42),
       "SVR (rbf)": sc(SVR(C=100))}
def bench(X, y):
    cv = KFold(5, shuffle=True, random_state=42)
    out = {}
    for name, m in zoo.items():
        r = cross_validate(m, X, y, cv=cv, scoring=("neg_root_mean_squared_error", "r2"))
        out[name] = (-r["test_neg_root_mean_squared_error"].mean(), r["test_r2"].mean())
    return pd.DataFrame(out, index=["RMSE", "R2"]).T.round(3)
diab = bench(Xd, yd)
elec = bench(Xp, yp)

board = pd.concat({"diabetes": diab, "synthetic demand": elec}, axis=1)

On the real diabetes data the simple linear family does well and fancy models give little extra, because the signal is mostly linear and noisy. On the curved synthetic demand data, models that can bend (polynomial, trees, forests, boosting, SVR) clearly beat the plain line. No model wins everywhere, which is why we compare.

Honest note. The synthetic table was built with a known curve, so it shows what nonlinear models can do. It says nothing about real electricity demand.

#Algorithm chooser

Algorithm Explainable Handles curves Needs scaling Speed on big data Start here when
Linear / multiple very no no (yes for penalties) fast you need a baseline or explanations
Polynomial + ridge medium smooth curves yes fast one or two features curve
Ridge / lasso / elastic net high no yes fast many or related features
KNN medium yes yes slow to predict small data, local patterns
Decision tree very yes no fast you need readable rules
Random forest low yes no medium strong default for tables
Gradient boosting low yes no medium you want the best accuracy
SVR low yes (kernel) yes slow on big data small to medium data, smooth target

#10.12 (Advanced) SVR and when it earns its place

What it does: support vector regression (SVR) fits a smooth curve while ignoring small errors. How it works: it tries to keep every point within a tube of width epsilon around the curve and only penalises points outside it; a kernel (the rbf kernel is the usual choice) lets the curve bend. Works best when the data is small to medium and scaled. Struggles when there are many rows (training slows quickly) or the settings are untuned. Key settings: C (higher fits training points harder), epsilon (tube width), kernel, gamma.

for C in (1, 10, 100, 1000):
    svr = make_pipeline(StandardScaler(), SVR(C=C)).fit(Xptr, yptr)
    print(f"C={C:4d}  train R2 {svr.score(Xptr, yptr):.3f} | test R2 {svr.score(Xpte, ypte):.3f}")

C=   1  train R2 0.358 | test R2 0.362
C=  10  train R2 0.913 | test R2 0.910
C= 100  train R2 0.961 | test R2 0.956
C=1000  train R2 0.965 | test R2 0.960

Small C underfits because the target is in the hundreds of megawatts and the tube is too forgiving; a larger C fits the curve. Tune C and gamma together with a grid search (Part 12).

Using it in the real world. Example 1, maize price: features such as rainfall, last season's price, fuel cost and month; target price per bag in Ksh. Validate on the most recent season, not a random split, because prices drift. Example 2, electricity demand: use temperature forecasts and calendar flags; judge by MAE in megawatts and by the worst days, since under-forecasting a peak is costly. Example 3, loan exposure: predict how much of a limit a borrower will draw; use a linear or boosted model and keep it explainable for the credit committee. How regression fails: the world shifts (a drought, a tax change), a feature is unavailable at prediction time (leakage), or the model is used far outside its training range. Monitor: log live predictions, compare with actuals each month, and retrain when MAE rises above the level you agreed.

Key takeaways
  • Regression predicts a number; score it with MAE, RMSE, R2 or MAPE and always compare with a baseline.
  • Start with linear regression: it is fast, explainable and a strong baseline.
  • Check the residuals; patterns in them mean the model is missing something.
  • Ridge, lasso and elastic net tame overfitting; lasso also removes weak features.
  • Trees, forests and boosting capture curves and thresholds; boosting often scores highest but needs tuning.
  • Compare models with the same cross-validation folds, then pick the simplest one that is good enough.
