Classification

Teach a model to choose between classes: yes or no, and one of many. You learn five classic algorithms, how to judge them honestly, and how to turn probabilities into business decisions.

In this part

  • Fit logistic regression, k-nearest neighbours, naive Bayes, a decision tree and an SVM
  • Read a confusion matrix and compute precision, recall, F1, ROC AUC and PR curves
  • Choose a decision threshold using the cost of each kind of mistake
  • Handle multi-class problems, imbalanced classes and uncalibrated probabilities
You need first Part 9 and Part 10Time 5 to 7 hours

#11.1 What Classification Is

Classification predicts a category. Will this loan default (yes or no)? Is this M-Pesa transaction fraud? Which of three species is this penguin? When there are two categories it is binary classification. With three or more it is multi-class.

Most classifiers do not jump straight to a label. They first give a probability for each class, then a threshold turns the probability into a decision (for example, 'flag if the probability is above 0.5'). Keeping these two steps apart is the key idea of this Part.

We start with the Wisconsin breast-cancer measurements that ship with scikit-learn (BSD licence). Each row is a tumour sample with 30 numeric measurements. We label malignant = 1, because that is the case we most want to catch.

import numpy as np, pandas as pd
import matplotlib.pyplot as plt
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split
from sklearn.dummy import DummyClassifier

data = load_breast_cancer(as_frame=True)
X = data.data
y = (data.target == 0).astype(int)          # 1 = malignant, 0 = benign
print("rows, columns:", X.shape)
print("share malignant:", round(y.mean(), 3))

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, stratify=y, random_state=42)
base = DummyClassifier(strategy="most_frequent").fit(X_train, y_train)
print("baseline accuracy (always say benign):", round(base.score(X_test, y_test), 3))

rows, columns: (569, 30)
share malignant: 0.373
baseline accuracy (always say benign): 0.629

The stratify=y option keeps the malignant share the same in train and test. The baseline model ignores every measurement and always predicts the majority class. Any real model must beat it, otherwise it has learned nothing.

Common mistake. A model that is 'accurate' can still be useless. If only 5 in 100 customers default, a model that approves everybody is 95 percent accurate and catches no defaulters. Always compare with the baseline and look beyond accuracy (section 11.3).

#11.2 Logistic Regression

What it does. Despite the name, logistic regression is a classifier. It gives the probability that a row belongs to class 1.

How it works. It adds up the features with weights, like linear regression (score = w1x1 + w2x2 + ... + b), then squeezes the score into the range 0 to 1 with the S-shaped sigmoid curve. Large positive scores become probabilities near 1, large negative scores near 0. Training finds the weights that make the observed labels most likely.

  • Works best when the classes are roughly separable by a straight boundary, you want probabilities, and you need to explain each feature's effect.
  • Struggles when the true boundary is curved or has feature interactions, unless you add those features yourself.
  • Key settings: C (inverse regularisation strength: smaller C means a simpler model), penalty (l2 by default), class_weight, and max_iter.
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score

logit = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))
logit.fit(X_train, y_train)
pred = logit.predict(X_test)
print("test accuracy:", round(accuracy_score(y_test, pred), 3))

proba = logit.predict_proba(X_test)[:, 1]
print("first 5 probabilities:", proba[:5].round(3))
print("first 5 labels      :", pred[:5])

test accuracy: 0.965
first 5 probabilities: [0.999 0.004 1.    0.    0.035]
first 5 labels      : [1 0 1 0 0]

Scaling matters here because the penalty on the weights treats all features alike. The pipeline scales inside the model so the test data is scaled with training statistics only (see Part 9 on leakage). Which features push the probability up?

coef = pd.Series(logit[-1].coef_[0], index=X.columns)
print(coef.sort_values().round(2).iloc[[0, 1, 2, -3, -2, -1]])

compactness error         -0.93
fractal dimension error   -0.60
mean compactness          -0.47
worst symmetry             1.04
radius error               1.27
worst texture              1.37
dtype: float64

Positive weights raise the chance of malignant, negative weights lower it. Because the features were standardised, the weights are comparable in size.

Rule of thumb. Logistic regression is where to start. It is fast, hard to overfit, gives probabilities, and its weights can be explained to a credit committee. Beat it before you reach for something fancier.

#11.3 Reading the Mistakes: Confusion Matrix, Precision, Recall, F1

Accuracy counts all correct answers equally. But the two kinds of mistake rarely cost the same. A confusion matrix counts all four outcomes, where 'positive' means class 1 (malignant here).

Predicted 0 Predicted 1
Actually 0 True negative (TN) False positive (FP): false alarm
Actually 1 False negative (FN): missed case True positive (TP) 
from sklearn.metrics import confusion_matrix, precision_score, recall_score, f1_score

tn, fp, fn, tp = confusion_matrix(y_test, pred).ravel()
print("TN", tn, "| FP", fp, "| FN", fn, "| TP", tp)
print("accuracy :", round((tp + tn) / (tp + tn + fp + fn), 3))
print("precision:", round(precision_score(y_test, pred), 3), "= TP / (TP + FP)")
print("recall   :", round(recall_score(y_test, pred), 3), "= TP / (TP + FN)")
print("F1       :", round(f1_score(y_test, pred), 3))

TN 89 | FP 1 | FN 4 | TP 49
accuracy : 0.965
precision: 0.98 = TP / (TP + FP)
recall   : 0.925 = TP / (TP + FN)
F1       : 0.951
  • Precision: of the cases we flagged, how many were really positive? High precision means few false alarms.
  • Recall (also called sensitivity): of all real positives, how many did we catch? High recall means few misses.
  • F1 is the harmonic mean of precision and recall. It is high only when both are high, so one good number cannot hide a bad one.
  • Specificity: of all real negatives, how many did we clear? It is recall for class 0.

Use recall when a miss is expensive (cancer screening, fraud). Use precision when a false alarm is expensive (freezing a good customer's account). The picture below shows the same matrix as a heatmap.

from sklearn.metrics import ConfusionMatrixDisplay
BLUE, GREEN, GREY, DARK, AMBER = "#1F5FD6", "#2BB38A", "#9CA3AF", "#0B2A4A", "#B45309"
fig, ax = plt.subplots(figsize=(4.6, 3.8))
ConfusionMatrixDisplay.from_predictions(
    y_test, pred, display_labels=["benign", "malignant"], cmap="Blues", ax=ax, colorbar=False)
ax.set_title("Logistic regression: confusion matrix on the test set")
ax.set_xlabel("Predicted class"); ax.set_ylabel("Actual class")
plt.tight_layout(); plt.savefig("p11_confusion.png", dpi=130); plt.close()
print("saved p11_confusion.png")

saved p11_confusion.png

The off-diagonal cells are the mistakes. Read the bottom-left cell as cancers we missed.

Practice and solution. Practice: a fraud model flags 50 transactions and 40 are truly fraud. There were 80 fraud transactions in total. Precision = 40/50 = 0.80 and recall = 40/80 = 0.50. The model is right when it speaks, but misses half of the fraud.

#11.4 k-Nearest Neighbours

What it does. It classifies a new row by looking at the k most similar rows in the training data and taking a vote.

How it works. There is no real training: the model just stores the data. To predict, it measures the distance from the new row to every stored row, picks the k closest and returns the majority class. The share of votes is the probability.

  • Works best when the data has few features, similar scales, and local patterns.
  • Struggles when features have different scales, there are many irrelevant features, or the data is huge (every prediction searches the whole training set).
  • Key settings: n_neighbors (k), weights ('uniform' or 'distance'), metric.
from sklearn.neighbors import KNeighborsClassifier

for k in [1, 5, 15, 45]:
    knn = make_pipeline(StandardScaler(), KNeighborsClassifier(n_neighbors=k))
    knn.fit(X_train, y_train)
    print(f"k={k:>2}  train acc={knn.score(X_train, y_train):.3f}  "
          f"test acc={knn.score(X_test, y_test):.3f}")

k= 1  train acc=1.000  test acc=0.937
k= 5  train acc=0.977  test acc=0.958
k=15  train acc=0.962  test acc=0.965
k=45  train acc=0.951  test acc=0.951

A tiny k follows every wiggle of the training data (it memorises: train accuracy is perfect at k=1). A huge k smooths too much. This is the bias-variance trade-off from Part 9 in one setting.

raw = KNeighborsClassifier(n_neighbors=5).fit(X_train, y_train)
scaled = make_pipeline(StandardScaler(), KNeighborsClassifier(n_neighbors=5)).fit(X_train, y_train)
print("without scaling:", round(raw.score(X_test, y_test), 3))
print("with scaling   :", round(scaled.score(X_test, y_test), 3))

without scaling: 0.923
with scaling   : 0.958

Common mistake. Distance-based models (k-NN, SVM) need scaled features. Otherwise a column measured in thousands, such as area, drowns out a column measured in decimals.

#11.5 Naive Bayes

What it does. It computes the probability of each class from how typical the feature values are for that class.

How it works. It uses Bayes' rule: the chance of a class given the evidence is proportional to the class's overall frequency times how likely the evidence is within that class. It is called naive because it assumes the features are independent given the class. That is rarely true, yet the model often ranks cases well anyway. Training is just counting means and spreads, so it is extremely fast.

  • Works best when you have little data, many features, or text (word counts).
  • Struggles when features are strongly correlated; its probabilities are often overconfident (see calibration in 11.11).
  • Key settings: GaussianNB for numeric features (var_smoothing), MultinomialNB for counts (alpha).
from sklearn.naive_bayes import GaussianNB

nb = GaussianNB().fit(X_train, y_train)
print("test accuracy:", round(nb.score(X_test, y_test), 3))
print("class priors (benign, malignant):", nb.class_prior_.round(3))

test accuracy: 0.944
class priors (benign, malignant): [0.627 0.373]

Naive Bayes shines on text. Here is a tiny, made-up set of SMS-style messages to flag scam texts. The model counts words per class.

from sklearn.feature_extraction.text import CountVectorizer
from sklearn.naive_bayes import MultinomialNB

texts = ["win free airtime now", "send pin to claim prize", "free prize claim now",
         "meeting at the shop at 5", "your M-Pesa balance is low", "see you at church sunday",
         "claim your free loan now", "lunch at 1 pm tomorrow", "confirm pin to win cash",
         "fare to town is 100 shillings"]
labels = [1, 1, 1, 0, 0, 0, 1, 0, 1, 0]            # 1 = scam (synthetic examples)
spam = make_pipeline(CountVectorizer(), MultinomialNB()).fit(texts, labels)
new = ["free cash prize now", "see you at the shop"]
print(dict(zip(new, spam.predict_proba(new)[:, 1].round(2).tolist())))

{'free cash prize now': 0.99, 'see you at the shop': 0.01}

#11.6 Decision Trees

What it does. It asks a chain of yes/no questions about the features and ends in a class, like a flowchart.

How it works. At each step the tree picks the feature and cut-off that best separates the classes, measured by how much impurity (mixing of classes, e.g. Gini) drops. It repeats on each side until a stopping rule is hit. A leaf's class proportions give the probability.

  • Works best when you need readable rules, the data mixes numeric and categorical features, and the relationships are non-linear. No scaling needed.
  • Struggles when it grows deep: a full tree memorises the training data and is unstable (small data changes give a very different tree).
  • Key settings: max_depth, min_samples_leaf, criterion, class_weight.
from sklearn.tree import DecisionTreeClassifier, export_text

for d in [1, 2, 4, 8, None]:
    t = DecisionTreeClassifier(max_depth=d, random_state=42).fit(X_train, y_train)
    print(f"max_depth={str(d):>4}  train={t.score(X_train, y_train):.3f}  "
          f"test={t.score(X_test, y_test):.3f}")

max_depth=   1  train=0.930  test=0.888
max_depth=   2  train=0.955  test=0.895
max_depth=   4  train=0.979  test=0.895
max_depth=   8  train=1.000  test=0.958
max_depth=None  train=1.000  test=0.958

A tree with no depth limit scores 1.000 on training data: it memorised it. Deeper trees fit the training data better, but test scores bounce around because one test set is small and the tree is unstable. Here are the rules of a depth-2 tree.

tree2 = DecisionTreeClassifier(max_depth=2, random_state=42).fit(X_train, y_train)
print(export_text(tree2, feature_names=list(X.columns)))

|--- worst perimeter <= 112.80
|   |--- worst concave points <= 0.18
|   |   |--- class: 0
|   |--- worst concave points >  0.18
|   |   |--- class: 1
|--- worst perimeter >  112.80
|   |--- mean texture <= 14.95
|   |   |--- class: 0
|   |--- mean texture >  14.95
|   |   |--- class: 1

A credit officer can read these rules line by line, which is why single trees remain popular for scorecard-style decisions. Part 12 combines many trees into forests for accuracy.

#11.7 Support Vector Machines

What it does. It finds the boundary that separates the classes with the widest possible street (margin) between them.

How it works. Only the points nearest the boundary, the support vectors, matter. A linear SVM draws a straight boundary. The RBF kernel lets the boundary bend by measuring similarity between points, so each point has a zone of influence. Two settings control the shape: C (how hard to punish training mistakes) and gamma (how small each point's zone of influence is).

  • Works best when you have a medium number of rows (up to tens of thousands), many features, and clear margins between classes.
  • Struggles when the data is huge (training is slow), or you need probabilities (they are bolted on and slow).
  • Key settings: kernel, C, gamma ('scale' is a good start), class_weight.
from sklearn.svm import SVC

for kern in ["linear", "rbf"]:
    svm = make_pipeline(StandardScaler(), SVC(kernel=kern, C=1.0)).fit(X_train, y_train)
    n_sv = svm[-1].n_support_.sum()
    print(f"{kern:>6}: test acc={svm.score(X_test, y_test):.3f}  support vectors={n_sv}")

linear: test acc=0.958  support vectors=36
   rbf: test acc=0.972  support vectors=103

SVMs give a signed distance from the boundary with decision_function. It works as a ranking score, which is all that ROC curves need.

svm = make_pipeline(StandardScaler(), SVC(kernel="rbf", C=1.0)).fit(X_train, y_train)
print("decision scores:", svm.decision_function(X_test)[:5].round(2))
print("their labels   :", svm.predict(X_test)[:5])

decision scores: [ 0.38 -1.61  1.63 -0.37 -0.89]
their labels   : [1 0 1 0 0]

Practice and solution. Practice: why must you scale features before an RBF SVM? Because the kernel uses distances. A feature with large numbers would dominate every distance and the other features would barely count.

#11.8 ROC Curve, AUC and the Precision-Recall Curve

A threshold of 0.5 is only one choice. Moving it trades false alarms for misses. The ROC curve shows every trade-off at once: for each threshold it plots the true positive rate (recall) against the false positive rate (false alarms among real negatives). The AUC (area under the curve) summarises it: 1.0 is perfect ranking and 0.5 is no better than a coin flip. AUC is the chance that a random positive gets a higher score than a random negative.

First, compare all five models fairly with 5-fold cross-validation on the training set, scoring by AUC.

from sklearn.model_selection import cross_val_score, StratifiedKFold

models = {
    "logistic": make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000)),
    "k-NN": make_pipeline(StandardScaler(), KNeighborsClassifier(n_neighbors=15)),
    "naive Bayes": GaussianNB(),
    "tree (depth 4)": DecisionTreeClassifier(max_depth=4, random_state=42),
    "SVM (RBF)": make_pipeline(StandardScaler(), SVC(kernel="rbf")),
}
cv = StratifiedKFold(5, shuffle=True, random_state=42)
rows = {}
for name, m in models.items():
    s = cross_val_score(m, X_train, y_train, cv=cv, scoring="roc_auc")
    rows[name] = [s.mean().round(3), s.std().round(3)]
print(pd.DataFrame(rows, index=["mean AUC", "std"]).T)

                mean AUC    std
logistic           0.991  0.009
k-NN               0.987  0.005
naive Bayes        0.986  0.006
tree (depth 4)     0.916  0.031
SVM (RBF)          0.994  0.004

Now draw the ROC and precision-recall curves on the held-out test set. The precision-recall curve plots precision against recall as the threshold moves. It is the better picture when positives are rare, because ROC can look rosy when negatives are plentiful.

from sklearn.metrics import roc_curve, precision_recall_curve
from sklearn.metrics import roc_auc_score, average_precision_score

def score(m, Xs):
    return m.decision_function(Xs) if hasattr(m, "decision_function") else m.predict_proba(Xs)[:, 1]

fig, (a1, a2) = plt.subplots(1, 2, figsize=(10, 3.8))
cols = [BLUE, GREEN, GREY, AMBER, DARK]
for (name, m), c in zip(models.items(), cols):
    s = score(m.fit(X_train, y_train), X_test)
    fpr, tpr, _ = roc_curve(y_test, s)
    pr, rc, _ = precision_recall_curve(y_test, s)
    a1.plot(fpr, tpr, color=c, label=f"{name} ({roc_auc_score(y_test, s):.3f})")
    a2.plot(rc, pr, color=c, label=f"{name} ({average_precision_score(y_test, s):.3f})")
a1.plot([0, 1], [0, 1], "--", color=GREY)
a1.set(title="ROC curve (AUC in brackets)", xlabel="False positive rate",
       ylabel="True positive rate")
a2.set(title="Precision-recall curve (AP in brackets)", xlabel="Recall", ylabel="Precision")
a1.legend(fontsize=7, loc="lower right"); a2.legend(fontsize=7, loc="lower left")
plt.tight_layout(); plt.savefig("p11_roc_pr.png", dpi=130); plt.close()
print("saved p11_roc_pr.png")

saved p11_roc_pr.png

Curves that hug the top-left corner (ROC) or top-right corner (precision-recall) are better. When several curves overlap, the models are practically tied and you should pick the simpler or faster one.

Common mistake. Plot ROC and precision-recall from test-set scores, and never choose a threshold on the test set you also use for the final report. Use validation data or cross-validation for tuning and keep the test set for one final check.

#11.9 Many Classes: Wine, Iris and Penguins

With more than two classes, the same algorithms work. Logistic regression uses the softmax function (one probability per class, summing to 1); trees, k-NN and naive Bayes handle multi-class natively; SVMs split the problem into several binary ones internally. Metrics are computed per class and then averaged:

  • macro average: treat every class equally (good when small classes matter)
  • weighted average: weight each class by its size
  • micro average: pool all decisions first (for single-label problems this equals accuracy)
from sklearn.datasets import load_wine
from sklearn.metrics import classification_report

wine = load_wine(as_frame=True)
Xw_tr, Xw_te, yw_tr, yw_te = train_test_split(
    wine.data, wine.target, test_size=0.3, stratify=wine.target, random_state=42)
wmodel = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000)).fit(Xw_tr, yw_tr)
print(classification_report(yw_te, wmodel.predict(Xw_te), target_names=wine.target_names))

              precision    recall  f1-score   support

     class_0       0.95      1.00      0.97        18
     class_1       1.00      0.95      0.98        21
     class_2       1.00      1.00      1.00        15

    accuracy                           0.98        54
   macro avg       0.98      0.98      0.98        54
weighted avg       0.98      0.98      0.98        54

#11.10 Choosing the Threshold with Costs

A lender cares about money, not F1. Let us build a synthetic credit-default table (made-up borrowers, generated with a fixed seed; it describes no real lender) and choose the threshold that minimises cost.

rng = np.random.default_rng(7)
n = 5000
credit = pd.DataFrame({
    "income_ksh": rng.lognormal(10.9, 0.5, n).round(-2),
    "debt_ratio": rng.beta(2, 5, n).round(3),
    "late_payments": rng.poisson(0.8, n),
    "age": rng.integers(21, 65, n),
    "loan_ksh": rng.lognormal(10.0, 0.6, n).round(-2)})
z = (-4.6 + 5.0 * credit.debt_ratio + 0.7 * credit.late_payments
     - 0.8 * (np.log(credit.income_ksh) - 10.9) + 0.4 * (np.log(credit.loan_ksh) - 10.0)
     - 0.02 * (credit.age - 40))
credit["default"] = (rng.random(n) < 1 / (1 + np.exp(-z))).astype(int)
print("synthetic data; default rate:", round(credit["default"].mean(), 3))

Xc = credit.drop(columns="default"); yc = credit["default"]
Xc_tr, Xc_te, yc_tr, yc_te = train_test_split(Xc, yc, test_size=0.3, stratify=yc, random_state=42)
credit_lr = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000)).fit(Xc_tr, yc_tr)
pc = credit_lr.predict_proba(Xc_te)[:, 1]
print("test AUC:", round(roc_auc_score(yc_te, pc), 3))

Suppose approving a borrower who then defaults loses Ksh 40,000 on average (a false negative), while rejecting a good borrower loses Ksh 4,000 of interest income (a false positive). These costs are assumptions for the demo. We sweep the threshold and add up the cost at each.

COST_FN, COST_FP = 40_000, 4_000
ths = np.linspace(0.01, 0.80, 80)
costs = []
for t in ths:
    flag = pc >= t                                  # flag = reject the application
    fn = ((~flag) & (yc_te == 1)).sum()
    fp = (flag & (yc_te == 0)).sum()
    costs.append(fn * COST_FN + fp * COST_FP)
costs = np.array(costs)
best = ths[costs.argmin()]
cost_at_half = (((pc < 0.5) & (yc_te == 1)).sum() * COST_FN
                + ((pc >= 0.5) & (yc_te == 0)).sum() * COST_FP)
print("best threshold:", round(best, 2), "| cost Ksh", f"{costs.min():,.0f}")
print("cost at 0.50  : Ksh", f"{cost_at_half:,.0f}")
print("theory, FP/(FP+FN):", round(COST_FP / (COST_FP + COST_FN), 3))

best threshold: 0.1 | cost Ksh 2,856,000
cost at 0.50  : Ksh 5,768,000
theory, FP/(FP+FN): 0.091

When a miss costs ten times a false alarm, the cheapest threshold is far below 0.5: it pays to be suspicious. The theoretical rule (reject when the probability exceeds cost_FP / (cost_FP + cost_FN)) lands close to the empirical best, as long as the probabilities are well calibrated (section 11.11).

Variation. Business teams often need a capacity limit instead (for example, analysts can review only 100 transactions a day). Then rank by probability and take the top 100: the threshold is whatever probability the 100th case has.

#11.11 Imbalanced Classes and Calibrated Probabilities (Advanced)

Defaults, fraud and churn are usually imbalanced: the positive class is rare. Models trained to maximise accuracy may then ignore it. Three remedies exist, all applied to the training set only:

  • Class weights: make mistakes on the rare class count more (class_weight="balanced").
  • Oversampling: repeat (or synthesise) rare-class rows.
  • Undersampling: drop some common-class rows.
def report(name, model, Xa, ya, Xb, yb):
    model.fit(Xa, ya)
    p = model.predict(Xb)
    auc = roc_auc_score(yb, model.predict_proba(Xb)[:, 1])
    return [name, round(precision_score(yb, p), 3), round(recall_score(yb, p), 3),
            round(f1_score(yb, p), 3), round(auc, 3)]

def lr(**kw):
    return make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000, **kw))

# by hand: oversample the training defaulters until both classes are the same size
r = np.random.default_rng(0)
pos = np.flatnonzero(yc_tr.to_numpy() == 1); neg = np.flatnonzero(yc_tr.to_numpy() == 0)
idx = np.r_[neg, r.choice(pos, size=len(neg), replace=True)]
neg_keep = r.choice(neg, size=len(pos), replace=False)         # undersample the majority
idx_under = np.r_[neg_keep, pos]

rows = [report("plain", lr(), Xc_tr, yc_tr, Xc_te, yc_te),
        report("class_weight", lr(class_weight="balanced"), Xc_tr, yc_tr, Xc_te, yc_te),
        report("oversample", lr(), Xc_tr.iloc[idx], yc_tr.iloc[idx], Xc_te, yc_te),
        report("undersample", lr(), Xc_tr.iloc[idx_under], yc_tr.iloc[idx_under], Xc_te, yc_te)]
cols = ["method", "precision", "recall", "F1", "AUC"]
print(pd.DataFrame(rows, columns=cols).to_string(index=False))

At the default 0.5 threshold, all three remedies raise recall and lower precision. The AUC barely changes, because the ranking of customers is almost the same: resampling mostly moves the best threshold, which you can also do directly (section 11.10). So reweighting is often just an expensive way to change the threshold, but it can help models that otherwise ignore the rare class during training, such as trees.

#Calibration: do the probabilities mean what they say?

A model is calibrated if, among cases it scores at 0.2, about 20 percent are truly positive. Reweighting breaks this (the model thinks positives are common), and so do naive Bayes and SVMs. Fix it by fitting a small mapping on held-out data with CalibratedClassifierCV (sigmoid or isotonic). The Brier score (mean squared error of the probabilities; lower is better) measures calibration.

from sklearn.calibration import CalibratedClassifierCV, calibration_curve
from sklearn.metrics import brier_score_loss

raw = lr(class_weight="balanced").fit(Xc_tr, yc_tr)
cal = CalibratedClassifierCV(lr(class_weight="balanced"), method="sigmoid", cv=5).fit(Xc_tr, yc_tr)
p_raw = raw.predict_proba(Xc_te)[:, 1]
p_cal = cal.predict_proba(Xc_te)[:, 1]
print("mean predicted default rate, raw       :", round(p_raw.mean(), 3))
print("mean predicted default rate, calibrated:", round(p_cal.mean(), 3))
print("actual default rate                    :", round(yc_te.mean(), 3))
print("Brier raw:", round(brier_score_loss(yc_te, p_raw), 4),
      "| Brier calibrated:", round(brier_score_loss(yc_te, p_cal), 4))

fig, ax = plt.subplots(figsize=(5.2, 4))
for p, lab, c in [(p_raw, "class_weight=balanced", AMBER), (p_cal, "after calibration", BLUE)]:
    frac, mean_p = calibration_curve(yc_te, p, n_bins=8, strategy="quantile")
    ax.plot(mean_p, frac, "o-", color=c, label=lab)
ax.plot([0, 1], [0, 1], "--", color=GREY, label="perfect")
ax.set(title="Reliability diagram (synthetic credit data)",
       xlabel="Predicted probability", ylabel="Observed default rate")

plt.tight_layout(); plt.savefig("p11_calibration.png", dpi=130); plt.close()

Points on the dashed diagonal mean honest probabilities. The reweighted model sits above it: it over-predicts risk. After calibration the points follow the diagonal. This matters whenever the probability itself is used, for example to price a loan or to compute expected loss.

#11.12 Choosing a Classifier, and Using It in the Real World

Algorithm Good first choice for Needs scaling Curved boundary Probabilities Explainable Main risk
Logistic regression Baseline, scorecards Yes No (add features) Good Very Misses interactions
k-NN Small, low-dimensional data Yes Yes Rough Medium Slow on big data
Naive Bayes Text, tiny data No Limited Overconfident Medium Correlated features
Decision tree Readable rules No Yes (boxes) Coarse Very Overfits when deep

A practical order of work: baseline, then logistic regression, then a tree-based ensemble (Part 12), judged on the same cross-validation folds with the metric that fits the business. Simplicity wins ties.

Using it in the real world. Credit scoring. Data: past loans with a clear definition of default (for example 90 days past due) and application features known at decision time. Validate on later months than you trained on, not a random split, and report AUC plus the cost at the chosen threshold. It fails when the lender changes policy (the past no longer resembles the future) and when rejected applicants have no outcome (selection bias). Monitor the share of applicants in each score band and the realised default rate per band every month. Keep a logistic model as the explainable benchmark.

Fraud screening. Fraud is rare, so use precision-recall curves, set the threshold from the number of cases analysts can review, and retrain often because fraudsters adapt. Churn. For a SACCO or telco, score members monthly, contact the top slice, and measure the real saving with a small control group that is not contacted.

Key takeaways
  • Classification outputs probabilities; a threshold turns them into decisions.
  • Always beat a baseline, and look past accuracy to the confusion matrix, precision, recall and F1.
  • Logistic regression is the explainable starting point; k-NN and SVM need scaling; trees need no scaling but overfit when deep; naive Bayes is fast and good with text.
  • ROC AUC measures ranking; the precision-recall curve is better for rare positives.
  • Choose the threshold from the cost of each mistake, not from habit.
  • Resample only the training data, and calibrate probabilities before using them as risk.
