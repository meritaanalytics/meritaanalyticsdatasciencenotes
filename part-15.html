Reinforcement Learning

How an agent learns by trial and error: bandits, Markov decision processes and Q-learning, built from scratch.

In this part

  • Explain exploration versus exploitation and test two ways to balance them
  • Describe a Markov decision process, the discount factor and the Bellman idea in plain words
  • Train a Q-learning agent in numpy and read its learned policy
  • Know where reinforcement learning is used, and where it is risky

#15.1 Learning from rewards

In supervised learning (Part 9) every example comes with the right answer. In reinforcement learning (RL) nobody gives the right answer. An agent tries actions, sees what happens, and gets a number called a reward. Good outcomes give high rewards. Over many tries the agent learns what to do.

Term Meaning Shop restocking example
Agent The decision maker The program that places orders
Environment Everything the agent cannot control Customers, suppliers, the market
State What the agent sees now Units of stock left on the shelf
Action A choice the agent can make Order 0, 1, 2 or 3 units
Reward Score for the last step Profit from sales minus costs
Policy The rule: state -> action If stock is 1, order 3
Value Total reward expected from here on How good it is to hold 3 units today

The loop is always the same: the agent sees a state, picks an action, the environment returns a reward and a new state, and the loop repeats. The goal is not the biggest reward now. It is the biggest total reward over time.

Key idea. Actions change the future. Selling more today may leave empty shelves tomorrow. This link between today's action and later rewards is what makes RL different from ordinary prediction.

#15.2 Exploration versus exploitation

Suppose you can send one of five promotional SMS messages to customers. You do not know which message gets the most replies. If you always send the best one so far, you may miss a better one (too much exploitation). If you keep trying new ones, you waste sends (too much exploration). Every RL agent must balance the two.

This small problem is called a multi-armed bandit: several choices ('arms'), each with an unknown chance of reward, and no states at all. It is the simplest form of RL. The simulation below uses five messages with synthetic reply rates that the agent cannot see.

#15.3 Multi-armed bandits: epsilon-greedy and UCB

Epsilon-greedy picks a random arm with small probability epsilon, otherwise the arm with the best average so far. UCB (upper confidence bound) adds a bonus to arms that were tried few times, so uncertain arms get a fair chance and the bonus shrinks as evidence grows. Regret is the reward lost compared with always choosing the truly best arm.

import numpy as np
true_p = np.array([0.05, 0.08, 0.12, 0.10, 0.06])   # synthetic reply rates, hidden from the agent

def run(policy, steps=1500, seed=0, eps=0.1, c=0.3):
    rng = np.random.default_rng(seed)
    n = np.zeros(5); mean = np.zeros(5); regret = []; total = 0.0
    for t in range(1, steps + 1):
        if n.min() == 0:
            a = int(np.argmin(n))                       # try every arm once
        elif policy == "eps":
            a = int(rng.integers(5)) if rng.random() < eps else int(np.argmax(mean))
        else:
            a = int(np.argmax(mean + c * np.sqrt(2 * np.log(t) / n)))
        r = float(rng.random() < true_p[a])
        n[a] += 1; mean[a] += (r - mean[a]) / n[a]      # running average
        total += true_p.max() - true_p[a]; regret.append(total)
    return np.array(regret)

reg = {p: np.mean([run(p, seed=s) for s in range(40)], axis=0) for p in ["eps", "ucb"]}
for p in reg: print(p, "average regret after 1500 sends:", round(reg[p][-1], 2))

eps average regret after 1500 sends: 30.01
ucb average regret after 1500 sends: 31.28
import matplotlib.pyplot as plt
BLUE, GREEN, GREY, DARK, AMBER = "#1F5FD6", "#2BB38A", "#9CA3AF", "#0B2A4A", "#B45309"
plt.figure(figsize=(10, 3.6))
plt.plot(reg["eps"], color=BLUE, label="epsilon-greedy (eps = 0.1)")
plt.plot(reg["ucb"], color=GREEN, label="UCB")
plt.title("Cumulative regret: reply rate lost versus always sending the best message")
plt.xlabel("Messages sent"); plt.ylabel("Cumulative regret (replies lost)")
plt.legend(); plt.tight_layout(); plt.savefig("p15_bandit.png", dpi=130); plt.close()
print("saved p15_bandit.png")

Regret grows fastest at the start, while the methods are still learning which message works.

A flatter curve is better. Epsilon-greedy keeps exploring at rate epsilon forever, so its regret keeps growing at a steady slope; UCB explores less as it becomes sure. The result depends on settings: UCB has a bonus scale (c in the code), and a bonus that is too large wastes sends when arms differ only a little. Try c = 1.4 and eps = 0.05 and compare.

Use it. Bandits power real 'A/B/n' tests that shift traffic to winners while the test runs: message wording, app banners, loan offers. Common mistake: judging an arm from very few tries.

#15.4 Markov decision processes and the Bellman idea

Bandits have no states. Most real problems do: your action changes where you are next. A Markov decision process (MDP) describes this with four things: states, actions, rewards, and transition chances (what state you land in after an action). Markov means the current state holds everything needed to decide; the history does not matter further.

A reward in the far future is worth less than one now (money later is uncertain). The discount factor gamma, a number between 0 and 1, expresses this. The total score is reward1 + gammareward2 + gamma^2reward3 and so on. A gamma near 0 makes the agent short-sighted. A gamma near 1 makes it patient.

rewards = [-1, -1, -1, -1, 10]          # four steps costing 1 each, then a goal worth 10
for gamma in [0.0, 0.5, 0.9, 0.99]:
    total = sum(r * gamma ** k for k, r in enumerate(rewards))
    print(f"gamma = {gamma:<4}  discounted return = {total:.2f}")

gamma = 0.0   discounted return = -1.00
gamma = 0.5   discounted return = -1.25
gamma = 0.9   discounted return = 3.12
gamma = 0.99  discounted return = 5.67

The Bellman idea in plain words: the value of a situation equals the reward you get now plus the discounted value of the best situation you can reach next. It turns a long-term question ('what is the best plan?') into a one-step question ('what is best now, given what I know about what comes next?'). Q-learning, next, applies this idea again and again.

#15.5 Q-learning on a small gridworld

What it does. Q-learning learns a table Q(state, action): the expected total reward of taking that action in that state and then acting well. How it works. After each step the agent nudges its Q value toward (reward + gamma * best Q of the next state). The nudge size is the learning rate alpha. With enough episodes the table converges to good values and the best action in each state is the policy.

Our world is a 4 x 4 grid. The agent starts top-left and wants the goal at bottom-right (reward +10). Each step costs 1, so short paths score better. One cell is a pit (reward -10, episode ends).

import numpy as np
N = 4; GOAL = (3, 3); PIT = (1, 2)
MOVES = {0: (-1, 0), 1: (1, 0), 2: (0, -1), 3: (0, 1)}      # up, down, left, right
ARROW = {0: "^", 1: "v", 2: "<", 3: ">"}

def step(s, a):
    r, c = s[0] + MOVES[a][0], s[1] + MOVES[a][1]
    if not (0 <= r < N and 0 <= c < N): r, c = s                # walls: stay put
    s2 = (r, c)
    if s2 == GOAL: return s2, 10.0, True
    if s2 == PIT: return s2, -10.0, True
    return s2, -1.0, False

def train(method="q", episodes=600, alpha=0.2, gamma=0.95, eps=0.1, seed=1):
    rng = np.random.default_rng(seed)
    Q = np.zeros((N, N, 4)); history = []
    def pick(s): return int(rng.integers(4)) if rng.random() < eps else int(np.argmax(Q[s]))
    for ep in range(episodes):
        s, done, total, a = (0, 0), False, 0.0, None
        a = pick(s)
        for _ in range(60):
            s2, r, done = step(s, a)
            a2 = pick(s2)
            target = r if done else r + gamma * (Q[s2].max() if method == "q" else Q[s2][a2])
            Q[s][a] += alpha * (target - Q[s][a])
            s, a, total = s2, a2, total + r
            if done: break
        history.append(total)
    return Q, np.array(history)

Q, hist_q = train("q")
print("mean reward, first 50 episodes:", round(hist_q[:50].mean(), 2))
print("mean reward, last 50 episodes: ", round(hist_q[-50:].mean(), 2))

mean reward, first 50 episodes: -1.26
mean reward, last 50 episodes:  3.98

The agent starts by wandering and ends by reaching the goal quickly, so the average reward rises. Now read the learned policy: for every cell, the action with the highest Q value.

def show_policy(Q):
    for r in range(N):
        row = []
        for c in range(N):
            if (r, c) == GOAL: row.append("G")
            elif (r, c) == PIT: row.append("X")
            else: row.append(ARROW[int(np.argmax(Q[r, c]))])
        print("  ".join(row))
show_policy(Q)

v  v  >  v
>  v  X  v
>  >  v  v
>  >  >  G

G is the goal and X is the pit. Follow the arrows from the top-left corner: they lead to G while walking around X. Nobody told the agent the map; it learned it from rewards.

Setting What it controls Typical range
alpha (learning rate) How far each update moves Q 0.05 to 0.5
gamma (discount) How much the future counts 0.9 to 0.99
epsilon Share of random exploratory actions 0.05 to 0.2, often decayed
episodes How long the agent practises Hundreds to millions

Works best when states and actions are few enough to store in a table and you can simulate many tries. Struggles when the state space is huge (every pixel of a screen) or each try is costly.

#15.6 SARSA versus Q-learning

SARSA is a close cousin. Q-learning updates toward the BEST next action (off-policy: it learns about the greedy plan even while exploring). SARSA updates toward the action it ACTUALLY takes next, including random exploratory ones (on-policy). Because SARSA counts its own exploration mistakes, it tends to learn safer routes near hazards; Q-learning tends to learn bolder, shorter ones.

Qs, hist_s = train("sarsa")
print("Q-learning last 100 episodes mean reward:", round(hist_q[-100:].mean(), 2))
print("SARSA      last 100 episodes mean reward:", round(hist_s[-100:].mean(), 2))
print("SARSA policy:")
show_policy(Qs)

Q-learning last 100 episodes mean reward: 3.26
SARSA      last 100 episodes mean reward: 3.89
SARSA policy:
v  v  <  v
v  v  X  v
>  v  >  v
>  >  >  G

In a small world like this the two give similar policies. The difference matters in tasks with a steep cliff next to the shortest path, where exploration slips are expensive.

#15.7 A Kenyan scenario: restocking a shop

A small shop sells a fast item, such as 1-litre cooking oil. Each morning the owner sees how many units are left (0 to 5) and orders 0 to 3 units, which arrive at once. Demand that day is random (synthetic). Selling a unit earns Ksh 30 profit, holding a unit costs Ksh 2 a day, and a customer turned away costs Ksh 15 in goodwill. This is a real MDP: stock is the state and orders are the action.

import numpy as np
CAP, RNG_DEMAND = 5, [0, 1, 2, 3]; P_DEMAND = [0.2, 0.35, 0.3, 0.15]   # synthetic demand

def day(stock, order, rng):
    stock = min(CAP, stock + order)
    d = int(rng.choice(RNG_DEMAND, p=P_DEMAND))
    sold = min(stock, d); lost = d - sold
    left = stock - sold
    return left, 30 * sold - 2 * left - 15 * lost - 5 * order       # Ksh 5 per unit ordered

rng = np.random.default_rng(7)
Qs = np.zeros((CAP + 1, 4)); stock = 3
for t in range(40000):
    eps = max(0.05, 1 - t / 20000)
    a = int(rng.integers(4)) if rng.random() < eps else int(np.argmax(Qs[stock]))
    s2, r = day(stock, a, rng)
    Qs[stock, a] += 0.1 * (r + 0.95 * Qs[s2].max() - Qs[stock, a])
    stock = s2
policy = Qs.argmax(axis=1)
for s in range(CAP + 1): print(f"stock {s} -> order {policy[s]}")

stock 0 -> order 3
stock 1 -> order 2
stock 2 -> order 0
stock 3 -> order 0
stock 4 -> order 0
stock 5 -> order 0

Compare the learned rule with two simple rules by simulating the same 3,000 days for each.

def evaluate(rule, days=3000, seed=99):
    rng = np.random.default_rng(seed); stock, total = 3, 0.0
    for _ in range(days):
        stock, r = day(stock, rule(stock), rng); total += r
    return total / days

rules = {"learned policy": lambda s: int(policy[s]), "never order": lambda s: 0,
         "always order 2": lambda s: 2}
for name, rule in rules.items(): print(f"{name:<15} average profit per day: Ksh {evaluate(rule):.1f}")

learned policy  average profit per day: Ksh 31.0
never order     average profit per day: Ksh -21.4
always order 2  average profit per day: Ksh 26.3

The learned policy should beat both fixed rules because it reacts to stock: it orders more when shelves are low and stops when they are full. Check the printed profits above to see by how much.

Using it in the real world. Data you need: a simulator or at least a year of daily stock, sales and order records. Validate: test the policy on days it never trained on, and compare with the owner's current habit, not with doing nothing. How it fails: demand changes at month end, festivals or rain, or the supplier is late, and the model has never seen it. Monitor: track profit per day and stockouts against the old method, and keep a human able to override orders.

#15.8 Applications of reinforcement learning

Area Agent decides Reward signal
Recommendations Which item or offer to show Click, purchase, watch time
Pricing Price or discount today Profit over time
Stock replenishment How much to order Profit minus holding and stockout cost
Dispatch (e.g. boda-boda) Which rider takes which request Short waits, fuel saved

Games Next move Win or lose
Language models How to answer Human ratings (see RLHF in Part 16)

RLHF (reinforcement learning from human feedback) is how chat assistants are polished: people rank answers, a reward model learns those preferences, and RL nudges the language model toward answers people prefer. Part 16 explains it in plain words.

#15.9 Limits and safety

  • Data hungry: agents often need millions of tries, so most are trained in simulators, not on real customers.
  • Reward hacking: the agent maximises the number you wrote, not what you meant. A delivery agent rewarded for 'fast drop-offs' may drop parcels at the wrong gate.
  • Unsafe exploration: random actions are fine in a game, dangerous with real money, machines or people.
  • Hard to debug: results change a lot between random seeds; always test several.
  • Shifting worlds: a policy learned last year may fail when customers or prices change.

Safe practice. Design rewards carefully, add hard limits the agent cannot break (maximum order size, price floors), try it in simulation first, then in a small live pilot with human oversight.

#15.10 Deep Q-networks and policy gradients (Advanced)

A table cannot store a chess position or a screen image. A deep Q-network (DQN) replaces the table with a neural network (Part 14) that takes a state and outputs one Q value per action. Two tricks keep training stable: a replay buffer (learn from random old experiences, not only the latest) and a slowly updated target network (a frozen copy used to compute targets).

import torch, torch.nn as nn
torch.manual_seed(0); torch.set_num_threads(2)
q_net = nn.Sequential(nn.Linear(4, 32), nn.ReLU(), nn.Linear(32, 2))   # 4 state numbers -> 2 actions
state = torch.tensor([[0.1, -0.2, 0.05, 0.3]])
print("Q values for each action:", q_net(state).detach().numpy().round(3))
# one learning step would use: loss = (q_net(s)[a] - (r + gamma * target_net(s2).max())) ** 2

Q values for each action: [[-0.115 -0.072]]

Policy gradient methods skip Q values and learn the policy itself: a network outputs the probability of each action, and actions that led to high total reward are made more likely. They handle continuous actions (a steering angle) better. Modern methods such as PPO, used in RLHF, are refined policy-gradient algorithms.

Method Learns Good for
Tabular Q-learning A Q table Small, discrete problems
DQN Q values with a neural network Large state spaces, few actions
Policy gradient / PPO The policy directly Continuous actions, language model tuning
Bandits Reward of each arm One-step choices, A/B/n tests
Key takeaways
  • RL learns from rewards by trial and error: agent, environment, state, action, reward, policy.
  • Balance exploration and exploitation: epsilon-greedy and UCB are simple, effective choices.
  • An MDP plus a discount factor lets an agent value the future; the Bellman idea links now and later.
  • Q-learning learns a table of action values; the best value per state is the policy.
  • SARSA learns from the moves it really makes and is usually more cautious.
  • Rewards define behaviour: guard against reward hacking and unsafe exploration.
